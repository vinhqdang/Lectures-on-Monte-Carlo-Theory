\section{Canonical Form of a DCP}
% ============================================================

\begin{frame}[allowframebreaks]{What Is Disciplined Convex Programming?}

  Convex optimization is special: when the objective function is
  \textbf{convex} and all constraints define a \textbf{convex feasible
  region}, then every local minimum is automatically a \emph{global}
  minimum.  This guarantee is enormously valuable in practice because it
  means no matter which starting point a solver uses, it will converge
  to the true best answer --- not merely a locally decent one.

  The difficulty, however, is \emph{knowing} whether a given problem is
  truly convex.  For small hand-crafted examples this can be checked with
  calculus, but for realistic engineering or data-science problems with
  hundreds of interleaved functions, manual verification is error-prone
  and impractical to automate without a disciplined framework.

  \begin{block}{The Core Challenge}
    Checking convexity of an expression requires applying calculus rules
    (second-derivative tests, composition theorems, etc.) to every
    sub-expression in the problem.  As problems grow in size and complexity,
    this becomes tedious and nearly impossible to do reliably by hand.
    We therefore need a \emph{systematic, mechanical} procedure that a
    computer can execute automatically.
  \end{block}

  \begin{alertblock}{DCP: Disciplined Convex Programming --- Definition}
    A \textbf{disciplined convex program (DCP)} is a convex optimization
    problem that is written according to a fixed set of \emph{grammatical
    rules}, so that automated software can (1) verify its convexity, and
    (2) convert it into a standard \emph{canonical form} accepted by
    high-performance numerical solvers.  The word ``disciplined'' means
    the problem writer follows the grammar; ``programming'' here means
    mathematical programming (optimisation), not computer programming.
  \end{alertblock}

  \begin{columns}
    \begin{column}{0.55\textwidth}
      The figure on the right illustrates the DCP workflow.  A user writes
      a problem using DCP syntax; the system checks the grammar
      (verification); converts it to canonical form (canonicalization); and
      hands it to a solver.  The key building blocks are \emph{atoms} ---
      a curated library of primitive mathematical functions whose convexity
      properties are pre-certified.  Every expression in a DCP is built by
      composing atoms.
    \end{column}
    \begin{column}{0.42\textwidth}
      \includegraphics[width=\textwidth]{fig_dcp_canonical.pdf}
    \end{column}
  \end{columns}

  \begin{alertblock}{Key Insight}
    DCP separates \emph{modelling} (writing the problem in human-readable
    form) from \emph{solving} (running numerical algorithms).  The user
    never hand-derives gradients, reformulations, or solver-specific
    data structures; the DCP system handles all of that automatically and
    provably correctly.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{Canonical Form of a Convex Program}

  Every convex optimization problem, no matter how it is originally
  stated, can be cast into a \emph{standard form} that unambiguously
  specifies the objective function and every constraint.  This standard
  form is what the DCP framework targets and what solvers expect.

  \begin{block}{Standard Convex Problem --- Eq.\ 14.1}
    \[
      \underset{\mathbf{x}}{\mathrm{minimize}}\quad f_0(\mathbf{x})
      \qquad
      \text{subject to}\quad
      \begin{cases}
        f_i(\mathbf{x}) \leq 0 & i = 1,\ldots,m\\[4pt]
        h_j(\mathbf{x}) = 0    & j = 1,\ldots,p
      \end{cases}
    \]
  \end{block}

  \begin{block}{Notation --- Every Symbol Explained}
    \begin{itemize}
      \item $\mathbf{x} \in \mathbb{R}^n$ (``\textbf{x} bold, in
            R-n'') is the \emph{decision variable}: an $n$-dimensional
            vector of real numbers that we are free to choose in order
            to minimise the objective.  Think of each component
            $x_1, x_2, \ldots, x_n$ as one ``knob'' we can turn.
      \item $f_0(\mathbf{x})$ (``f-zero of x'') is the \emph{objective
            function}: the quantity we want to make as small as possible.
            DCP requires $f_0$ to be \textbf{convex} --- meaning its
            graph looks like a bowl that opens upward, with no
            hidden valleys.
      \item $f_i(\mathbf{x})$ (``f sub i of x'', for $i = 1,\ldots,m$)
            are the $m$ \emph{inequality constraint functions}.  The
            requirement $f_i(\mathbf{x}) \leq 0$ says that the solution
            must lie inside the region where $f_i$ is non-positive.
            DCP requires each $f_i$ to also be \textbf{convex}, so the
            feasible region for that constraint is a convex set.
      \item $h_j(\mathbf{x})$ (``h sub j of x'', for $j = 1,\ldots,p$)
            are the $p$ \emph{equality constraint functions}.  These
            must be \textbf{affine} (of the form
            $\mathbf{a}^{\top}\mathbf{x} - b$, i.e., a linear function
            of $\mathbf{x}$).  The reason is explained in the alert
            below.
      \item $m$ is the total number of inequality constraints; $p$ is
            the total number of equality constraints; $n$ is the number
            of decision variables.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read This Formula}
    We are searching over all $n$-dimensional vectors $\mathbf{x}$ for
    the one that minimises $f_0(\mathbf{x})$ while staying inside the
    \emph{feasible region} --- the set of all $\mathbf{x}$ satisfying
    every constraint.  Because every $f_i$ is convex, each feasible
    region $\{f_i \leq 0\}$ is itself a convex set, and the
    intersection of convex sets is convex, so the full feasible region
    is convex.  Minimising a convex function over a convex set is
    always a well-behaved problem: there is exactly one globally optimal
    value (though there may be multiple optimal points), and any local
    minimiser is a global minimiser.
  \end{alertblock}

  \begin{alertblock}{Why Must Equality Constraints Be Affine?}
    An equality constraint $h(\mathbf{x}) = 0$ is logically equivalent
    to two simultaneous inequality constraints: $h(\mathbf{x}) \leq 0$
    \emph{and} $h(\mathbf{x}) \geq 0$.  The first requires $h$ to be
    \textbf{convex}; the second, rewritten as $-h(\mathbf{x}) \leq 0$,
    requires $-h$ to be convex, i.e., $h$ to be \textbf{concave}.  A
    function that is simultaneously convex and concave must be
    \textbf{affine}.  This is why DCP forbids nonlinear equality
    constraints.
  \end{alertblock}

  \begin{block}{The Four DCP Requirements}
    A problem is a valid DCP only if it satisfies all four conditions:
    \begin{enumerate}
      \item \textbf{Product-free expressions.}  No expression may
            contain the product of two non-constant sub-expressions.
            For instance, $x_1 \cdot x_2$ (where both factors vary)
            is forbidden.  This restriction ensures curvature can be
            tracked symbolically through the expression.
      \item \textbf{Top-level curvature rules.}  The top-level role of
            each expression must match its curvature: a minimised
            objective must be convex, a maximised objective must be
            concave, an inequality left-hand side must be convex, and
            an equality must be affine.
      \item \textbf{Sign rules.}  The system tracks whether each
            constant coefficient is positive or negative, because
            multiplying a convex function by $-1$ turns it concave.
      \item \textbf{Composition rules.}  When one function is applied
            to the output of another, the DCP system checks whether
            the curvature and monotonicity (``increasing or
            decreasing'') of the outer function are compatible with the
            curvature of the inner expression.
    \end{enumerate}
  \end{block}

\end{frame}

% ────────────────────────────────────────────────────────────
\begin{frame}[allowframebreaks]{Running Example --- Verifying a Mixed-Norm Problem (Ex.\ 14.1)}

  To make the abstract definitions concrete, let us trace through a
  specific problem step by step and verify that every DCP rule is
  satisfied.  This running example will be used throughout the chapter.

  \begin{exampleblock}{The Problem to Verify}
    \[
      \underset{\mathbf{x}}{\mathrm{minimize}}\;
      \|\mathbf{A}\mathbf{x} - \mathbf{b}\|_1
      \qquad
      \text{subject to}\;
      \|\mathbf{C}\mathbf{x} - \mathbf{d}\|_{1.5} \leq 3
    \]
    with specific numerical matrices and vectors:
    \[
      \mathbf{A}=\begin{bmatrix}2&-1\\1&3\end{bmatrix},\quad
      \mathbf{b}=\begin{bmatrix}4\\-5\end{bmatrix},\quad
      \mathbf{C}=\begin{bmatrix}0&1\\3&-4\end{bmatrix},\quad
      \mathbf{d}=\begin{bmatrix}-1\\0\end{bmatrix}
    \]
  \end{exampleblock}

  \begin{block}{Notation --- Every Symbol in This Problem}
    \begin{itemize}
      \item $\mathbf{x} \in \mathbb{R}^2$ (``x bold in R-2'') is the
            two-dimensional decision vector with components $x_1$ and
            $x_2$.  This is the variable we will solve for.
      \item $\mathbf{A}$ and $\mathbf{C}$ are $2 \times 2$ matrices of
            \emph{fixed} (known) numbers --- they are not variables.
      \item $\mathbf{b}$ and $\mathbf{d}$ are fixed two-dimensional
            vectors.
      \item $\|\mathbf{v}\|_1$ (``L-one norm of v'') of a vector
            $\mathbf{v} = (v_1, v_2)$ equals $|v_1| + |v_2|$, the sum
            of the absolute values of all components.  More generally
            for $n$ components: $\|\mathbf{v}\|_1 = \sum_{k=1}^n
            |v_k|$.
      \item $\|\mathbf{v}\|_{1.5}$ (``L-1.5 norm of v'') is the
            $L_p$ norm with $p = 1.5$, defined as
            $\bigl(\sum_k |v_k|^{1.5}\bigr)^{1/1.5}$.  Any $L_p$
            norm with $p \geq 1$ is a convex function, because $p = 1$
            gives the convex $L_1$ norm and all larger $p$ give
            ``rounder'' unit balls that are still convex.
      \item The constraint $\|\mathbf{C}\mathbf{x} -
            \mathbf{d}\|_{1.5} \leq 3$ says: ``the $L_{1.5}$ distance
            between $\mathbf{C}\mathbf{x}$ and $\mathbf{d}$ must be at
            most~3.''
    \end{itemize}
  \end{block}

  \begin{block}{Step-by-Step DCP Verification}
    We verify the problem by checking each piece against the DCP rules.
    \begin{enumerate}
      \item The expression $\mathbf{A}\mathbf{x} - \mathbf{b}$ is the
            product of a \emph{fixed} matrix $\mathbf{A}$ with the
            variable vector $\mathbf{x}$, minus a constant.  This is an
            \textbf{affine} (linear) function of $\mathbf{x}$.  Affine
            functions are simultaneously convex and concave --- the
            mildest possible curvature.
      \item The $L_1$ norm $\|\cdot\|_1$ is a convex function listed
            in the atom library.  Applying a convex norm to an affine
            argument gives a \textbf{convex} function --- this follows
            from the composition rule (norms are nondecreasing in the
            absolute values of their inputs, and the affine argument
            satisfies the compatibility condition).
      \item Similarly, $\mathbf{C}\mathbf{x} - \mathbf{d}$ is affine,
            and $\|\cdot\|_{1.5}$ is convex, so their composition is
            \textbf{convex}.
      \item The constraint is of the form \emph{convex function}
            $\leq$ \emph{constant} (the number 3 is convex --- all
            constants are both convex and concave), which satisfies
            the DCP inequality rule.
      \item The objective asks to \emph{minimise} a \emph{convex}
            function, which is exactly what DCP requires.
    \end{enumerate}
    \textcolor{dcpgreen}{\textbf{Conclusion: this is a valid DCP.}}
  \end{block}

  \begin{alertblock}{Key Insight}
    Each check above is performed \emph{mechanically} by software,
    consulting only the atom library for curvature information.  The
    human writer never needs to invoke the mathematical definition of
    convexity directly.  This is the entire point of the DCP framework.
  \end{alertblock}

\end{frame}

% ────────────────────────────────────────────────────────────
\begin{frame}[allowframebreaks]{The Atom Library --- Building Blocks of DCP}

  The DCP framework rests on a curated \emph{atom library}: a catalogue
  of primitive mathematical functions for which the convexity properties
  have been pre-certified.  When you write a DCP expression, you are
  composing atoms together according to grammar rules, exactly as you
  compose words according to language rules.  As long as you stay within
  the grammar, convexity of the whole expression is guaranteed.

  \begin{columns}
    \begin{column}{0.55\textwidth}
      \includegraphics[width=\textwidth]{fig_atom_library.pdf}
    \end{column}
    \begin{column}{0.42\textwidth}
      \begin{block}{What Each Atom Records}
        For each function $f$ in the library, four pieces of information
        are stored:
        \begin{itemize}
          \item \textbf{Domain} --- the set of inputs for which $f$ is
                defined.  For example, $\log(x)$ requires $x > 0$.
          \item \textbf{Curvature} --- whether $f$ is convex, concave,
                or affine (linear) over its domain.
          \item \textbf{Monotonicity} (per argument) --- whether $f$ is
                nondecreasing or nonincreasing in each of its arguments.
                This information is essential for the composition rule.
          \item \textbf{Range} --- bounds on the output of $f$.  For
                example, $\sqrt{x} \geq 0$ always.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}

  \medskip

  \begin{block}{Common Atoms and Their Properties}
    \small
    \begin{tabular}{lllll}
      \toprule
      \textbf{Atom} & \textbf{Mathematical notation} & \textbf{Curvature} &
        \textbf{Monotonicity} & \textbf{Domain}\\
      \midrule
      Absolute value  & $|x|$              & Convex
        & Nonincreasing for $x < 0$; nondecreasing for $x > 0$
        & $\mathbb{R}$ (all reals)\\
      Square          & $x^2$              & Convex
        & Same as $|x|$ & $\mathbb{R}$\\
      Square root     & $\sqrt{x}$         & Concave
        & Nondecreasing & $x \geq 0$\\
      Natural log     & $\log(x)$          & Concave
        & Nondecreasing & $x > 0$\\
      Exponential     & $e^x$              & Convex
        & Nondecreasing & $\mathbb{R}$\\
      $L_p$ norm      & $\|\mathbf{v}\|_p$ & Convex
        & --- (depends on sign of each component) & $\mathbb{R}^n$, $p \geq 1$\\
      Maximum         & $\max(a,b)$        & Convex
        & Nondecreasing in both & $\mathbb{R}$\\
      \bottomrule
    \end{tabular}
  \end{block}

  \begin{block}{Sets as Atoms}
    Convex \emph{sets} can also be treated as atoms.  Some common examples:
    \begin{itemize}
      \item The non-negative orthant $\mathbb{R}^n_+ = \{\mathbf{x}
            \;:\; x_i \geq 0 \text{ for all } i\}$ (``R-n-plus'') is a
            convex set, used to represent non-negativity constraints on
            all variables.
      \item The positive semidefinite cone
            $\mathbb{S}^n_+ = \{X \in \mathbb{R}^{n\times n} \;:\;
            X = X^\top,\; \mathbf{v}^\top X \mathbf{v} \geq 0\text{ for all }\mathbf{v}\}$
            (``S-n-plus'', meaning all symmetric matrices with
            non-negative curvature) is used in semidefinite programming.
      \item The \emph{epigraph} (``epi'') and \emph{hypograph}
            (``hypo'') of a function (defined in Section~3) are convex
            sets closely associated with convex and concave functions
            respectively.
    \end{itemize}
  \end{block}

  \begin{alertblock}{Key Insight}
    The atom library is the heart of the DCP system.  Adding a new atom
    (with its certified curvature information) immediately extends the
    class of problems that DCP can handle, without any changes to the
    verification or canonicalization algorithms.
  \end{alertblock}

\end{frame}

\section{Verification of Convexity}
% ============================================================

\begin{frame}[allowframebreaks]{Verification --- The Two-Stage Pipeline}

  Once a problem is written in DCP notation, the software must determine
  whether it actually satisfies the convexity requirements.  This
  verification is done in \emph{two sequential stages}: a syntactic
  stage that checks the structure of the formula, and a semantic stage
  that propagates curvature labels.

  \begin{block}{Two-Stage Verification}
    \begin{enumerate}
      \item \textbf{Stage 1 --- Product-Free Check.}  The system scans
            every expression and confirms that no expression contains
            the product of two non-constant sub-expressions.  This stage
            is \emph{purely syntactic}: it does not reason about
            curvature at all, only about the algebraic structure of the
            formula.  It is fast and can be done in a single pass over
            the expression.
      \item \textbf{Stage 2 --- Rule Checking.}  The system constructs
            an \emph{expression tree} --- a tree-shaped representation
            where leaves are variables or constants and internal nodes
            are operations or atoms --- and then walks the tree from the
            leaves (bottom) up to the root (top), assigning a curvature
            label (\emph{convex} / \emph{concave} / \emph{affine} /
            \emph{neither}) to each node, and verifying the sign,
            composition, and top-level production rules at each step.
    \end{enumerate}
  \end{block}

  \begin{columns}
    \begin{column}{0.50\textwidth}
      Both stages are fully automatic.  If Stage~1 fails, the system
      reports which sub-expression contains a forbidden product and
      stops.  If Stage~2 finds a curvature violation, it reports the
      offending node in the tree so the user can fix the formulation.
      If both stages pass, the problem is a valid DCP and proceeds to
      canonicalization.
    \end{column}
    \begin{column}{0.47\textwidth}
      \includegraphics[width=\textwidth]{fig_verification_pipeline.pdf}
    \end{column}
  \end{columns}

  \begin{alertblock}{Key Insight}
    Verification runs in time proportional to the size of the
    expression (i.e., the number of operations), so it is essentially
    instantaneous even for large problems.  The cost of the verification
    step is negligible compared to the cost of solving the problem.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{Product-Free Expressions --- The First Filter}

  The product-free requirement is the first filter in DCP verification.
  Its purpose is to ensure that every expression can be written as a
  \emph{linear combination} of atom outputs, which makes it possible to
  track curvature symbolically through the formula.

  \begin{block}{Definition: Product-Free Expression (Eq.\ 14.5)}
    An expression $e$ is called \textbf{product-free} if and only if it
    can be written in the form:
    \[
      e \;=\; a \;+\; \mathbf{b}^{\top}\mathbf{x}
              \;+\; \sum_{j=1}^{q} c_j \, f_j(\mathbf{e}_j)
    \]
  \end{block}

  \begin{block}{Notation --- Every Symbol Explained}
    \begin{itemize}
      \item $a \in \mathbb{R}$ (``a in R'') is a real-valued
            \emph{constant}: a fixed number that does not depend on
            any variable.
      \item $\mathbf{b} \in \mathbb{R}^n$ (``b bold in R-n'') is a
            \emph{constant} vector of coefficients.
      \item $\mathbf{b}^{\top}\mathbf{x}$ (``b-transpose times x'',
            also written as the inner product $\langle \mathbf{b},
            \mathbf{x}\rangle$) equals $b_1 x_1 + b_2 x_2 + \cdots +
            b_n x_n$, which is an affine (linear) function of
            $\mathbf{x}$.  The $\top$ symbol (``superscript T'' or
            ``transpose'') turns the column vector $\mathbf{b}$ into a
            row vector so that the multiplication is defined.
      \item $\sum_{j=1}^{q}$ ($\Sigma$ (Sigma), meaning ``sum from
            $j$ equals 1 to $q$'') denotes the sum of $q$ terms, one
            for each atom call in the expression.
      \item $c_j$ is a \emph{constant} scalar coefficient for the
            $j$-th atom call.  It can be positive, negative, or zero,
            but it must not involve any variable.
      \item $f_j$ (``f sub j'') is the $j$-th atom from the atom
            library (for example, $\log$, $\|\cdot\|_2$, $\max$,
            $e^{(\cdot)}$).
      \item $\mathbf{e}_j$ (``e bold sub j'') is the vector of
            sub-expressions passed as arguments to atom $f_j$.
            Crucially, each component of $\mathbf{e}_j$ must itself be
            a product-free expression --- the definition is
            \emph{recursive}.  This recursion is what allows complex
            nested expressions to be classified.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read This Definition}
    A product-free expression is built from: (a) a constant $a$,
    plus (b) an affine (linear) term in the decision variables
    $\mathbf{x}$, plus (c) a weighted sum of atom evaluations, where
    the weights $c_j$ are all constants.  The only operations allowed
    are \textbf{addition}, \textbf{subtraction}, and \textbf{scalar
    multiplication by constants}.  No variable-times-variable products
    are permitted.  This restriction is what makes symbolic curvature
    tracking possible: the system only needs to look up the curvature
    of each atom $f_j$ in the library, and the rest is just addition
    with known signs.
  \end{alertblock}

  \begin{columns}
    \begin{column}{0.50\textwidth}
      \begin{exampleblock}{Valid (Product-Free) Examples}
        \begin{itemize}
          \item $3 + 2x_1 + \log(x_2)$: constant $3$, linear term
                $2x_1$, atom $\log(x_2)$ --- product-free because $2$
                is a constant multiplier, not a variable.
          \item $\max(x_1^2 - 3,\; x_2)$: the $\max$ atom applied to
                two sub-expressions, where $x_1^2$ is handled by the
                \texttt{square} atom --- product-free.
          \item $\|\mathbf{A}\mathbf{x} - \mathbf{b}\|_2$: the
                $L_2$-norm atom applied to an affine expression
                ($\mathbf{A}$ is a fixed matrix) --- product-free.
        \end{itemize}
      \end{exampleblock}
    \end{column}
    \begin{column}{0.47\textwidth}
      \begin{alertblock}{Invalid (Not Product-Free) Examples}
        \begin{itemize}
          \item $x_1 \cdot x_2$: product of two variables --- rejected.
          \item $x_1^2$ written as $x_1 \times x_1$: same issue.
                However, $x_1^2$ \emph{is} allowed if written as
                \texttt{square}$(x_1)$, using the designated atom
                with its pre-certified curvature.
          \item $\sin(x_1) \cdot \log(x_2)$: product of two
                non-constant sub-expressions --- rejected.
        \end{itemize}
      \end{alertblock}
    \end{column}
  \end{columns}

  \begin{block}{Important Note on $x^2$}
    The expression $x^2$ looks like a product, but the DCP system
    handles it through the \texttt{square} atom, which stores the
    curvature information directly: convex, nondecreasing for $x \geq 0$,
    nonincreasing for $x \leq 0$, with range $[0, \infty)$.  The atom
    library is the bridge that allows nonlinear functions while still
    maintaining the product-free property.  The key principle: any
    nonlinear function you use must appear as a named atom in the
    library, not as an explicit multiplication of variables.
  \end{block}

\end{frame}

% ────────────────────────────────────────────────────────────
\begin{frame}[allowframebreaks]{Sign Rules --- How Scaling Changes Curvature}

  Once an expression passes the product-free check, the system assigns
  curvature labels by applying \emph{sign rules}.  These rules govern
  how multiplying by a constant scalar, or adding two expressions
  together, affects whether the result is convex, concave, or affine.

  The intuition is geometric: a convex function looks like a bowl.
  Multiplying it by a positive constant scales the bowl but keeps it
  pointing upward (convex).  Multiplying by a negative number flips the
  bowl upside down, turning it into an arch (concave).

  \begin{block}{Sign Rules for Scaling by a Constant}
    Let $f(\mathbf{x})$ be a function with known curvature, and let
    $c$ be a constant real number (positive or negative).  Then:
    \begin{itemize}
      \item If $f$ is \textbf{convex} and $c > 0$, then
            $c \cdot f(\mathbf{x})$ is \textbf{convex}.
            Scaling a bowl upward keeps it a bowl.
      \item If $f$ is \textbf{convex} and $c < 0$, then
            $c \cdot f(\mathbf{x})$ is \textbf{concave}.
            Flipping a bowl upside down gives an arch.
      \item If $f$ is \textbf{concave} and $c > 0$, then
            $c \cdot f(\mathbf{x})$ is \textbf{concave}.
            Scaling an arch keeps it an arch.
      \item If $f$ is \textbf{concave} and $c < 0$, then
            $c \cdot f(\mathbf{x})$ is \textbf{convex}.
            Flipping an arch gives a bowl.
    \end{itemize}
    The pattern is: the curvature \emph{flips} when you multiply by
    a negative constant, and \emph{stays the same} for a positive
    constant.
  \end{block}

  \begin{block}{Sum Rules for Adding Two Functions}
    Adding two functions affects curvature as follows:
    \begin{columns}
      \begin{column}{0.50\textwidth}
        \begin{itemize}
          \item convex $+$ convex $=$ \textbf{convex}.
                Two bowls added together give a bowl.
          \item concave $+$ concave $=$ \textbf{concave}.
                Two arches added give an arch.
          \item affine $+$ convex $=$ \textbf{convex}.
                A flat plate added to a bowl gives a bowl.
          \item affine $+$ concave $=$ \textbf{concave}.
        \end{itemize}
      \end{column}
      \begin{column}{0.47\textwidth}
        \begin{itemize}
          \item convex $+$ concave $=$ \textbf{neither} (in general).
                A bowl plus an arch can give almost any shape.
          \item affine $+$ affine $=$ \textbf{affine}.
                Two flat plates sum to a flat plate.
        \end{itemize}
      \end{column}
    \end{columns}
  \end{block}

  \begin{exampleblock}{Worked Example: Classifying $3 + 2\log(1+x_1) - \sin(x_2)$}
    We classify this expression step by step, starting from the
    innermost sub-expressions.  We assume $x_1 \geq 0$ (so $1 + x_1
    \geq 1$, keeping $\log$ in its domain) and $x_2 \in [-\pi, 0]$.

    \medskip
    \textbf{Step 1.}  The natural logarithm $\log(1+x_1)$ is a
    \textbf{concave} function.  This is an atom in the library with
    known curvature.

    \medskip
    \textbf{Step 2.}  Multiplying by the positive constant $2$:
    $2\log(1+x_1)$ is \textbf{concave} (positive constant times
    concave stays concave by the sign rule).

    \medskip
    \textbf{Step 3.}  The sine function $\sin(x_2)$ on
    $x_2 \in [-\pi, 0]$ has a non-negative second derivative on this
    interval (specifically $-\sin(x_2) \geq 0$ there), so $\sin(x_2)$
    is \textbf{convex} on $[-\pi, 0]$.

    \medskip
    \textbf{Step 4.}  The coefficient of $\sin(x_2)$ in the full
    expression is $-1$ (negative), so $-\sin(x_2)$ is \textbf{concave}
    (negative constant times convex is concave).

    \medskip
    \textbf{Step 5.}  Adding:
    \begin{align*}
      \underbrace{3}_{\text{affine}} +
      \underbrace{2\log(1+x_1)}_{\text{concave}} +
      \underbrace{(-\sin(x_2))}_{\text{concave}}
    \end{align*}
    Affine $+$ concave $=$ concave; concave $+$ concave $=$
    \textbf{concave}.

    \medskip
    \textbf{Conclusion:} the entire expression is \textbf{concave}
    on the domain $\{x_1 \geq 0,\; x_2 \in [-\pi,0]\}$.
  \end{exampleblock}

\end{frame}

\begin{frame}[allowframebreaks]{Composition Rules --- Chaining Functions Together}

  The composition rule handles the most common pattern in practice:
  applying one function to the output of another.  For example,
  $1/g(\mathbf{x})$ composes the reciprocal function $f(t) = 1/t$ with
  $g(\mathbf{x})$.  The composition rule tells us when
  $f(g(\mathbf{x}))$ is convex or concave, based on the properties
  of $f$ and $g$ individually.

  The intuition: think of curvature as ``direction'' (convex $=$ curving
  up, concave $=$ curving down).  If the outer function is nondecreasing
  (it does not reverse direction), then the curvature of the inner
  function propagates unchanged.  If the outer function is nonincreasing
  (it reverses direction), then the curvature of the inner function
  flips.

  \begin{block}{Composition Theorem (Eqs.\ 14.3--14.4)}
    The composed function $f(\varepsilon_1, \ldots, \varepsilon_m)$,
    where $\varepsilon$ (epsilon) denotes each sub-expression argument,
    is \textbf{convex} if all of the following hold:
    \begin{itemize}
      \item $f$ is itself either affine or \textbf{convex}; and
      \item For each argument $\varepsilon_i$ (``epsilon sub i'',
            the $i$-th argument to $f$), one of the three cases applies:
        \begin{itemize}
          \item[$\triangleright$] $f$ is \emph{nondecreasing}
                (i.e., larger input gives larger output) in
                $\varepsilon_i$ over the range $\mathcal{R}$
                (``R, the effective range'') of $\varepsilon_i$,
                \emph{and} $\varepsilon_i$ is \textbf{convex}; or
          \item[$\triangleright$] $f$ is \emph{nonincreasing}
                (larger input gives smaller output) in $\varepsilon_i$
                over $\mathcal{R}$, \emph{and} $\varepsilon_i$ is
                \textbf{concave}; or
          \item[$\triangleright$] $\varepsilon_i$ is \textbf{affine}
                (in which case no monotonicity condition on $f$ is
                needed, because affine inputs are both convex and
                concave).
        \end{itemize}
    \end{itemize}
    Symmetric rules apply for establishing \textbf{concavity}.
  \end{block}

  \begin{alertblock}{How to Read This Theorem}
    Think of ``convex'' as ``curving up'' and ``concave'' as ``curving
    down''.  A nondecreasing outer function passes curvature through
    unchanged.  A nonincreasing outer function flips the curvature
    (just as multiplying by a negative number flips the sign).  So:
    nondecreasing outer + convex inner = convex (up through up stays up);
    nonincreasing outer + concave inner = convex (down then flipped =
    up).  Two ``flips'' cancel, preserving convexity.
  \end{alertblock}

  \begin{block}{Decomposition Consequence (Eq.\ 14.7)}
    When $f$ is convex and nondecreasing, the single constraint
    $f(g(\mathbf{x})) \leq y$ can be split into two simpler
    constraints using a fresh auxiliary variable $z$ (``z''):
    \[
      f(g(\mathbf{x})) \leq y \quad\iff\quad
      \begin{cases}f(z) \leq y\\[4pt]g(\mathbf{x}) \leq z\end{cases}
    \]
    This splitting is valid because $f$ is nondecreasing: if
    $g(\mathbf{x}) \leq z$ then $f(g(\mathbf{x})) \leq f(z) \leq y$.
    This splitting technique --- introducing a fresh variable for each
    function application --- is the basis of the canonicalization step
    described in Section~3.
  \end{block}

\end{frame}

\begin{frame}[allowframebreaks]{Composition Rules --- Worked Examples}

  Two detailed worked examples apply the composition theorem to verify
  whether specific composed expressions are convex.

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \begin{exampleblock}{Ex.\ 14.3: Is $f(g(\mathbf{x})) = 1/g(\mathbf{x})$ convex?}
        Here $f(t) = 1/t$ (the reciprocal function) and
        $g(\mathbf{x}) = 3 + 2\log(1+x_1) - \sin(x_2)$, the
        expression we already classified as \textbf{concave} with range
        contained in $[3, \infty)$ (since the minimum value of $g$ is
        $3$, achieved when $\log$ and the correction from $\sin$ are
        both at their minimum).

        \medskip
        \textbf{Step 1.}  From the previous example, $g$ is
        \textbf{concave} with effective range $\mathcal{R} \subseteq
        [3,\infty)$.

        \medskip
        \textbf{Step 2.}  The outer function $f(t) = 1/t$ is
        \textbf{convex and nonincreasing} for $t > 0$ (as $t$ grows,
        $1/t$ decreases; as $t$ shrinks toward 0, $1/t$ blows up
        convexly).

        \medskip
        \textbf{Step 3.}  Apply the composition theorem: $f$ is
        convex and \emph{nonincreasing}; $g$ is \emph{concave}.  This
        matches the second sub-case (nonincreasing outer + concave
        inner), so the composition is convex.

        \medskip
        \textbf{Step 4.}  Verify the range condition: $f$ is
        nonincreasing on $(0, \infty)$, and $\mathcal{R} \subseteq
        [3,\infty) \subset (0,\infty)$, so $f$ is indeed nonincreasing
        over the full range of $g$.

        \textcolor{dcpgreen}{\textbf{Conclusion:}} $1/g(\mathbf{x})$
        is \textbf{convex}.
      \end{exampleblock}
    \end{column}
    \begin{column}{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig_composition_max.pdf}
      \vspace{-4pt}
      \begin{block}{Ex.\ 14.5: Is $\max(\varepsilon(x_1), x_2)$ convex?}
        \small
        The $\max$ function is convex and nondecreasing in both
        arguments.  For the first argument $\varepsilon$:
        \begin{itemize}
          \item $\varepsilon = x_1$ (affine): $\max(x_1, x_2)$ is
                \textbf{convex} (affine argument, third sub-case).
          \item $\varepsilon = \sin(x_1)$ (neither convex nor concave
                on $\mathbb{R}$): the composition rule fails ---
                \textbf{not certified as convex}.
          \item $\varepsilon = x_1^2 - 3$ (convex via \texttt{square}
                atom): $\max$ is nondecreasing, argument is convex ---
                first sub-case applies --- \textbf{convex}.
          \item $\varepsilon = \log(x_1) - 1$ (concave): $\max$ is
                nondecreasing but argument is concave --- neither
                sub-case applies --- \textbf{not certified as convex}.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}

  \begin{alertblock}{Key Insight}
    The composition rule requires checking \emph{both} the curvature
    of the outer function \emph{and} its monotonicity over the specific
    range of the inner expression.  Both conditions must be satisfied
    simultaneously.  If either fails, the DCP system cannot certify
    convexity for that composition.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{Top-Level Production Rules}

  After the sign and composition rules have assigned curvature labels to
  all sub-expressions in the tree, the DCP system checks the
  \emph{top-level role} of each expression.  Each role --- objective to
  minimise, objective to maximise, inequality constraint, equality
  constraint --- has a required curvature.  This is the final gate
  before a problem is declared valid.

  \begin{block}{Top-Level Curvature Requirements}
    \begin{tabular}{lll}
      \toprule
      \textbf{Context} & \textbf{Required curvature} & \textbf{Concrete example}\\
      \midrule
      Minimise $f_0(\mathbf{x})$ & $f_0$ must be \textbf{convex}
        & $\min\;\|\mathbf{x}\|_2$\\[2pt]
      Maximise $f_0(\mathbf{x})$ & $f_0$ must be \textbf{concave}
        & $\max\;\log(\det X)$\\[2pt]
      Inequality $f(\mathbf{x}) \leq c$ & $f$ must be \textbf{convex};
        $c$ must be \textbf{concave} (or constant)
        & $\|g(\mathbf{x})\|_2 \leq 3$\\[2pt]
      Inequality $c \leq f(\mathbf{x})$ & $c$ must be \textbf{convex}
        (or constant); $f$ must be \textbf{concave}
        & $0 \leq \log(\mathbf{x})$\\[2pt]
      Equality $h(\mathbf{x}) = 0$ & $h$ must be \textbf{affine}
        & $\mathbf{A}\mathbf{x} = \mathbf{b}$\\
      \bottomrule
    \end{tabular}
  \end{block}

  \begin{alertblock}{Why These Rules Follow from Convex Analysis}
    Each rule is a consequence of convex analysis:
    \begin{itemize}
      \item Minimising a convex function gives a problem with a unique
            global minimum (or a convex set of equally-good minima).
      \item Maximising a concave function is equivalent (by multiplying
            by $-1$) to minimising a convex function --- same guarantee.
      \item An inequality $f(\mathbf{x}) \leq c$ with $f$ convex
            defines a convex sublevel set, i.e., a convex feasible
            region.
      \item An equality $h(\mathbf{x}) = 0$ simultaneously requires $h
            \leq 0$ (convex) and $-h \leq 0$ (also convex, i.e., $h$
            concave), so $h$ must be affine --- the only functions
            that are both convex and concave.
    \end{itemize}
  \end{alertblock}

  \begin{exampleblock}{Example: Nonlinear Equality Is Rejected}
    Suppose someone writes $x_1^2 + x_2^2 = 1$ (the unit circle) as an
    equality constraint.  The function $f(\mathbf{x}) = x_1^2 + x_2^2$
    is convex (a bowl) but \emph{not} concave (not an arch), so it
    cannot satisfy both inequality requirements simultaneously.  The DCP
    system will reject this with an informative error message.  The
    correct way to handle such a constraint is to relax it to an
    inequality $x_1^2 + x_2^2 \leq 1$ (a disk, which is convex) or to
    reformulate the problem entirely.
  \end{exampleblock}

\end{frame}

\begin{frame}[allowframebreaks]{Automatic Verification --- Expression Tree Walkthrough (Ex.\ 14.6)}

  The expression tree is the internal data structure used by DCP
  software to represent a formula.  Each leaf node is a constant or
  variable; each internal node is an operation or atom; and the root
  represents the whole expression.  Verification consists of a single
  bottom-up pass that assigns curvature labels as it goes.

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \begin{exampleblock}{Problem (Ex.\ 14.6)}
        \small
        \[
          \underset{x_1,x_2}{\mathrm{minimize}}\;
          \mathrm{pow}(a_1 x_1 + a_2 x_2 - b_1,\,2)
        \]
        \[
          \text{s.t.}\quad c_1 x_1 + c_2 x_2 = d,\quad
          \sqrt{\min(x_1, x_2)} \geq 1 - \log(x_2)
        \]
        where $a_1, a_2, b_1, c_1, c_2, d$ are known constants.
      \end{exampleblock}
      \begin{block}{Curvature Trace (Bottom-Up)}
        \small
        \texttt{minimize}\\
        \quad$\hookrightarrow$ \texttt{pow}($\varepsilon$, 2):
          \textcolor{dcpblue}{convex} --- squaring is convex\\
        \quad\quad$\hookrightarrow$ $-b_1 + a_1 x_1 + a_2 x_2$:
          \textcolor{dcpblue}{affine} --- linear in $x_1, x_2$\\
        \texttt{equality constraint:}\\
        \quad$\hookrightarrow$ $c_1 x_1 + c_2 x_2 - d$:
          \textcolor{dcpblue}{affine} \checkmark\\
        \texttt{inequality} $\geq$: concave $\geq$ convex \checkmark\\
        \quad$\hookrightarrow$ $\sqrt{\varepsilon}$:
          \textcolor{dcpgreen}{concave, nondecreasing}\\
        \quad\quad$\hookrightarrow$ $\min(\varepsilon, \varepsilon)$:
          \textcolor{dcpgreen}{concave, nondecreasing}\\
        \quad$\hookrightarrow$ $1 - \log(\varepsilon)$:
          \textcolor{dcpred}{convex} --- $-\log$ is convex
      \end{block}
    \end{column}
    \begin{column}{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig_expression_tree.pdf}
      \begin{block}{Domain Conditions Inferred Automatically}
        \small
        As the tree is traversed, the system automatically collects
        domain conditions implied by the atoms:
        \begin{itemize}
          \item $\log(x_2)$ requires $x_2 > 0$.
          \item $\sqrt{\min(x_1, x_2)}$ requires
                $\min(x_1, x_2) \geq 0$, i.e., both $x_1 \geq 0$
                and $x_2 \geq 0$.
          \item Together these imply $x_1 \geq 0$ and $x_2 > 0$,
                which the solver will enforce automatically as
                implicit constraints.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}

  \begin{alertblock}{Key Insight}
    The expression tree makes verification both \emph{complete} (every
    sub-expression is inspected) and \emph{efficient} (each node is
    visited exactly once, so the total work is proportional to the
    number of operations in the problem --- essentially instantaneous).
    This is far more reliable than manual convexity checking and does
    not require the user to understand the underlying mathematics.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{Canonicalization --- What It Is and Why It Matters}

  Once the DCP system has verified that the problem is convex, it
  performs \textbf{canonicalization}: a fully automatic transformation
  of the problem from the user's high-level, expressive form into a
  \emph{partitioned canonical form} that standard solvers can directly
  accept.  This transformation is always mathematically correct ---
  the canonical form has exactly the same optimal solution as the
  original problem.

  \begin{block}{Why Canonical Form Is Needed}
    Different convex solvers (SCS, ECOS, MOSEK, Clarabel, etc.) each
    accept problems in their own specific internal format.  By converting
    any valid DCP into a single canonical form, the CVXPY library can
    serve as a \emph{universal translation layer}: the user writes in
    expressive DCP notation, and the backend automatically generates the
    solver-specific input data.  This also enables the system to extract
    \emph{dual information} (Lagrange multipliers, sensitivity analysis,
    optimality certificates) in a uniform way.
  \end{block}

  \begin{block}{Partitioned Canonical Form (Eq.\ 14.8)}
    \[
      \underset{\mathbf{x}^{(1)},\ldots,\mathbf{x}^{(k)}}
      {\mathrm{minimize}}\quad
      d + \sum_{i=1}^{k}\bigl(\mathbf{c}^{(i)}\bigr)^{\top}\mathbf{x}^{(i)}
    \]
    \[
      \text{subject to}\quad
      \mathbf{x}^{(i)} \in S^{(i)}\;\;(i=1,\ldots,k),\qquad
      \sum_{i=1}^{k}\mathbf{A}^{(i)}\mathbf{x}^{(i)} = \mathbf{b}
    \]
  \end{block}

  \begin{block}{Notation --- Every Symbol in the Canonical Form}
    \begin{itemize}
      \item $\mathbf{x}^{(i)}$ (``x bold superscript i'', meaning the
            $i$-th block of variables) is one \emph{block} of decision
            variables.  The original problem's variables, plus all
            auxiliary variables introduced during canonicalization, are
            split into $k$ separate blocks.  The superscript here is a
            block index, not a power.
      \item $d$ is a real constant (a fixed numerical offset in the
            objective, which has no effect on the optimal solution but
            is needed to report the correct optimal value).
      \item $\mathbf{c}^{(i)}$ (``c bold superscript i'') is the linear
            cost vector for block $i$.  The objective is a simple
            \textbf{linear} (dot product) combination of all variables.
      \item $S^{(i)}$ (``S superscript i'') is a \textbf{convex cone}
            (or convex set) from the atom library --- for example, the
            non-negative orthant, the second-order cone, or the
            positive semidefinite cone.  Membership in $S^{(i)}$
            encodes all the nonlinear structure of the original problem
            in a form solvers understand natively.
      \item $\mathbf{A}^{(i)}$ (``A bold superscript i'') is a matrix
            of coupling coefficients.  The equality
            $\sum_{i=1}^k \mathbf{A}^{(i)}\mathbf{x}^{(i)} = \mathbf{b}$
            links the blocks together.  Outside this one equality, all
            blocks are completely independent.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read the Canonical Form}
    The objective is purely \textbf{linear} in all variables --- there
    is no quadratic or other nonlinear term.  All nonlinearity is hidden
    inside the set-membership constraints $\mathbf{x}^{(i)} \in
    S^{(i)}$.  The coupling equality
    $\sum_i \mathbf{A}^{(i)}\mathbf{x}^{(i)} = \mathbf{b}$ is the
    only link between blocks.  This block structure causes the
    Hessian (matrix of second derivatives) of the barrier function used
    by interior point solvers to be \textbf{block-diagonal}, which is
    far cheaper to invert than a dense matrix --- enabling dramatic
    speed improvements for large problems.
  \end{alertblock}

  \begin{block}{Two Steps of Canonicalization}
    Canonicalization proceeds in two steps:
    \begin{enumerate}
      \item \textbf{Linearization.}  Each atom call $f_j(\mathbf{e}_j)$
            in every expression is replaced by a fresh scalar variable
            $v_j$, and a constraint is added that ties $v_j$ to the
            atom's value.  After this step, the objective and all
            constraint expressions are \emph{affine} (linear) in the
            expanded set of original and auxiliary variables.
      \item \textbf{Graph implementation.}  Each atom constraint (e.g.,
            $f(u) \leq v$) is further expanded into its \emph{graph
            form} --- a set of linear or conic (second-order cone,
            semidefinite, etc.) constraints that characterise the
            epigraph or hypograph of the atom.  After this step, all
            constraints are in standard conic form.
    \end{enumerate}
  \end{block}

\end{frame}

% ────────────────────────────────────────────────────────────
\begin{frame}[allowframebreaks]{Linearization --- Replacing Atoms with Variables}

  Linearization is the first step of canonicalization.  Its goal is to
  replace every nonlinear atom call with a fresh auxiliary variable,
  making all expressions in the problem linear (affine) in the expanded
  variable set.  The nonlinearity is moved from the expressions into
  new constraints.

  \begin{block}{Linearization Process (Eqs.\ 14.9--14.11)}
    Starting from the product-free expression:
    \[
      a + \mathbf{b}^{\top}\mathbf{x} +
      \sum_{j=1}^{q} c_j\, f_j(\mathbf{e}_j)
    \]
    we introduce one new \emph{atom variable} $v_j$ for each atom call.
    The expression becomes the affine function:
    \[
      a + \mathbf{b}^{\top}\mathbf{x} + \mathbf{c}^{\top}\mathbf{v}
    \]
    where $\mathbf{v} = (v_1, \ldots, v_q)$ is the vector of new atom
    variables, and $\mathbf{c} = (c_1, \ldots, c_q)$ collects the
    original coefficients.

    For each $j = 1, \ldots, q$, the following constraint is added
    to tie $v_j$ to the actual atom value:
    \[
      \begin{cases}
        f_j(\mathbf{e}_j) \leq v_j
          & \text{if } f_j \text{ is \textbf{convex}}\\[6pt]
        f_j(\mathbf{e}_j) \geq v_j
          & \text{if } f_j \text{ is \textbf{concave}}
      \end{cases}
    \]
  \end{block}

  \begin{block}{Notation and Justification}
    \begin{itemize}
      \item $\mathbf{v}$ (``v bold'') is the vector of all $q$ newly
            introduced atom variables, one per atom call.  These are
            sometimes called \emph{epigraph variables} for convex atoms
            and \emph{hypograph variables} for concave atoms.
      \item $\mathbf{c} \in \mathbb{R}^q$ (``c bold in R-q'') collects
            the original scalar coefficients $c_j$ from the expression
            so that the substituted expression can be written compactly
            as $\mathbf{c}^{\top}\mathbf{v}$.
      \item \textbf{Why the inequality instead of equality?}  The
            constraint $f_j(\mathbf{e}_j) \leq v_j$ (for a convex atom
            contributing with a positive coefficient $c_j > 0$ to a
            minimisation) says ``$v_j$ is an upper bound on the atom's
            value.''  Since the optimiser minimises $c_j v_j$ and $c_j
            > 0$, it will drive $v_j$ as small as possible, forcing
            $v_j = f_j(\mathbf{e}_j)$ at optimality.  This
            \emph{tightness at optimality} is what makes the
            substitution correct --- the optimal solution of the
            linearized problem is identical to that of the original.
    \end{itemize}
  \end{block}

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \includegraphics[width=\textwidth]{fig_linearization.pdf}
    \end{column}
    \begin{column}{0.45\textwidth}
      \begin{alertblock}{Key Idea}
        Each atom call $f_j(\cdot)$ is replaced by a fresh placeholder
        variable $v_j$, plus a constraint that links $v_j$ to the
        actual atom value.  After linearization, the objective and all
        constraint \emph{expressions} are affine.  All nonlinearity has
        been concentrated into the new atom constraints, which are then
        handled in the graph-implementation step.
      \end{alertblock}
    \end{column}
  \end{columns}

\end{frame}

% ────────────────────────────────────────────────────────────
\begin{frame}[allowframebreaks]{Linearization --- Worked Numerical Example (Ex.\ 14.8)}

  Let us trace through the complete linearization of one concrete
  expression, step by step, to see exactly how the process introduces
  new variables and constraints.

  \begin{exampleblock}{Linearizing: $\mathrm{pow}\!\bigl(3 + 2\log(1+x_1) - \sin(x_2),\;{-1}\bigr)$}
    This expression computes the reciprocal (i.e., $1/z$, where
    $z = 3 + 2\log(1+x_1) - \sin(x_2)$) of the expression we
    have been studying.

    \medskip
    \textbf{Step 1 --- Identify the innermost affine arguments.}
    The innermost sub-expressions are $1 + x_1$ (argument to $\log$)
    and $x_2$ (argument to $\sin$).  Both are affine in $x_1$ and
    $x_2$, so no new variables are needed at this level.

    \medskip
    \textbf{Step 2 --- Handle the intermediate layer.}  The middle
    expression $3 + 2\log(1+x_1) - \sin(x_2)$ contains two atom
    calls: $\log$ (concave) and $\sin$ (convex on $[-\pi, 0]$).
    Introduce atom variables $v_1$ (for $\log$) and $v_2$ (for
    $\sin$), plus an argument alias $u_{1,1} = 1 + x_1$:
    \[
      3 + 2v_1 - v_2 \quad\text{subject to:}\quad
      \log(u_{1,1}) \geq v_1,\quad u_{1,1} = 1+x_1,\quad
      \sin(x_2) \leq v_2
    \]
    The $\geq$ for $\log$ reflects that it is concave (hypograph
    variable); the $\leq$ for $\sin$ reflects that it is convex
    (epigraph variable).

    \medskip
    \textbf{Step 3 --- Handle the outer layer.}  The atom
    $\mathrm{pow}(\cdot, -1)$ (the reciprocal, which is convex for
    positive arguments) is applied to the middle expression.  Introduce
    variable $v_3$ for the reciprocal and auxiliary argument variable
    $u_{3,1}$:
    \[
      v_3 \quad\text{subject to:}\quad
      \mathrm{pow}(u_{3,1}, -1) \leq v_3,\quad
      u_{3,1} = 3 + 2v_1 - v_2
    \]

    \medskip
    \textbf{Result.}  The full linearized form introduces
    \textbf{5 new variables}: $v_1, v_2, v_3, u_{1,1}, u_{3,1}$,
    and \textbf{5 new constraints} (one per new variable, plus the
    atom inequality constraints).  The original non-affine expression
    has been replaced by the simple affine expression $v_3$.  Every
    remaining function call is applied to an \emph{affine} argument,
    which is exactly what the graph-implementation step expects.
  \end{exampleblock}

\end{frame}

\begin{frame}[allowframebreaks]{Graph Implementations --- The Absolute Value}

  After linearization, each atom constraint has the form
  $f(u) \leq v$ or $f(u) \geq v$, where $u$ is affine.  The second
  step of canonicalization replaces each such constraint with its
  \emph{graph implementation}: a set of simpler linear or conic
  constraints that exactly characterise the same relationship without
  using the atom symbol $f$ directly.

  The name ``graph implementation'' comes from the fact that the set
  $\{(u, v) : f(u) \leq v\}$ is the \emph{epigraph} of $f$ --- the
  region on or above the graph of the function --- and we are
  implementing this set using basic linear or cone constraints.

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \begin{block}{Graph Expansion of $|x|$ (Eq.\ 14.13)}
        The absolute value $|x|$ is a nonlinear function (it has a
        kink at $x = 0$ and is not differentiable there).  However,
        it can be characterised exactly as the smallest $y$ that is
        simultaneously at least $x$ and at least $-x$:
        \[
          |x| \;\Rightarrow\;
          \begin{cases}
            \displaystyle\min_y\; y\\[4pt]
            \text{s.t.}\; y \geq x,\quad y \geq -x
          \end{cases}
        \]
        To see why: if $x \geq 0$, then the binding constraint is
        $y \geq x$, giving $y = x = |x|$.  If $x < 0$, then the
        binding constraint is $y \geq -x$, giving $y = -x = |x|$.
        Both constraints are linear in $(x, y)$, so the absolute
        value atom has been replaced by two linear inequalities.
        The kink disappears!
      \end{block}

      \begin{exampleblock}{Worked Example: Expanding $|2x + 3| \leq 5$}
        \small
        \textbf{After linearization:} introduce $v = |2x+3|$ and let
        $u = 2x + 3$ (affine).  The constraint becomes $v \leq 5$
        with atom constraint $|u| \leq v$.

        \textbf{After graph expansion:} replace $|u| \leq v$ with
        $v \geq u$ and $v \geq -u$.  Full linear system:
        \[
          v \geq u,\quad v \geq -u,\quad
          u = 2x+3,\quad v \leq 5.
        \]
        All constraints are now linear --- a standard LP.
      \end{exampleblock}
    \end{column}
    \begin{column}{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig_abs_graph.pdf}
    \end{column}
  \end{columns}

\end{frame}

\begin{frame}[allowframebreaks]{Epigraph and Hypograph --- Geometry of Graph Implementations}

  The absolute value example generalises: every graph implementation is
  derived from the \emph{epigraph} (for convex atoms) or the
  \emph{hypograph} (for concave atoms) of the function.  These are
  geometric objects that capture the ``above the graph'' and ``below
  the graph'' regions.

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \begin{block}{Definitions (Eq.\ 14.15)}
        The \textbf{epigraph} (from the Greek ``epi'' meaning
        ``above'') of a function $f$ is the set of all points that
        lie on or above the graph of $f$:
        \[
          \mathrm{epi}\,f \;=\;
          \bigl\{(\mathbf{x},y)\in\mathbb{R}^n\times\mathbb{R}
          \;\big|\; y \geq f(\mathbf{x})\bigr\}
        \]
        The \textbf{hypograph} (from the Greek ``hypo'' meaning
        ``below'') of $f$ is the set of all points that lie on or
        below the graph:
        \[
          \mathrm{hypo}\,f \;=\;
          \bigl\{(\mathbf{x},y)\in\mathbb{R}^n\times\mathbb{R}
          \;\big|\; y \leq f(\mathbf{x})\bigr\}
        \]
        The key mathematical facts are:
        \begin{itemize}
          \item $f$ is \textbf{convex} $\iff$ $\mathrm{epi}\,f$ is a
                \textbf{convex set}.
          \item $f$ is \textbf{concave} $\iff$ $\mathrm{hypo}\,f$ is
                a \textbf{convex set}.
        \end{itemize}
      \end{block}

      \begin{block}{Epigraphs and Hypographs in Graph Expansion}
        A convex atom constraint $f(\mathbf{x}) \leq y$ is the same
        as set membership in the epigraph:
        \[
          f(\mathbf{x}) \leq y \;\iff\;
          (\mathbf{x}, y) \in \mathrm{epi}\,f
        \]
        A concave atom constraint $f(\mathbf{x}) \geq y$ is membership
        in the hypograph:
        \[
          f(\mathbf{x}) \geq y \;\iff\;
          (\mathbf{x}, y) \in \mathrm{hypo}\,f
        \]
        Since $\mathrm{epi}\,f$ is a convex set when $f$ is convex
        (and $\mathrm{hypo}\,f$ is convex when $f$ is concave), both
        cases produce a valid convex constraint.
      \end{block}
    \end{column}
    \begin{column}{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig_epi_hypo.pdf}
      \vspace{4pt}
      \small\textit{Blue region: epigraph of $x^3$ on $x \geq 0$
      (convex function, convex region above the curve).  Red region:
      hypograph of $\log x$ (concave function, convex region below
      the curve).  Observe that both shaded regions are convex sets,
      i.e., any straight line connecting two points in the region
      lies entirely within it.}
    \end{column}
  \end{columns}

  \begin{alertblock}{How to Read This}
    The equivalence between a function inequality and set membership
    is the bridge between optimisation over functions and optimisation
    over sets (conic programming).  Every convex atom in the library
    has its epigraph described by known conic constraints (linear,
    second-order cone, semidefinite, etc.), so the DCP system can
    always produce a form that a specific numerical solver can process.
    The human never needs to derive these conic representations by
    hand.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{Graph Implementations --- $L_1$, $L_\infty$, $L_p$, and $L_2$ Norms}

  Norms are among the most frequently used atoms in DCP.  Here we
  show how four important norms are each converted to solver-ready
  form through their graph implementations.  In each case, the
  potentially complex norm expression becomes a small LP or conic
  programme.

  \begin{columns}
    \begin{column}{0.52\textwidth}
      \begin{block}{$L_1$ Norm as a Linear Programme (Ex.\ 14.9)}
        The $L_1$ norm $\|\mathbf{x}\|_1 = |x_1| + |x_2| + \cdots +
        |x_n|$ sums the absolute values of all components.  Its graph
        expansion bounds each component independently with its own
        auxiliary variable:
        \[
          \|\mathbf{x}\|_1 \;\Rightarrow\;
          \begin{cases}
            \min_{\mathbf{v}}\; \mathbf{1}^{\top}\mathbf{v}\\[2pt]
            \text{s.t.}\; -\mathbf{v} \leq \mathbf{x} \leq \mathbf{v}
          \end{cases}
        \]
        Here $\mathbf{v}$ (``v bold'') is a vector of $n$ auxiliary
        variables, one per component.  The all-ones vector
        $\mathbf{1}$ (``ones vector'') makes the objective the sum
        $v_1 + v_2 + \cdots + v_n$.  The component-wise constraint
        $-v_i \leq x_i \leq v_i$ means $v_i \geq |x_i|$, and since
        we minimise the sum, at optimality $v_i = |x_i|$ exactly.
      \end{block}

      \begin{block}{$L_\infty$ Norm as a Linear Programme}
        The $L_\infty$ (``L-infinity'') norm
        $\|\mathbf{x}\|_\infty = \max_i |x_i|$ is the largest
        absolute value among all components.  A single scalar
        auxiliary variable $v$ upper-bounds every component:
        \[
          \|\mathbf{x}\|_\infty \;\Rightarrow\;
          \begin{cases}
            \min_{v}\; v\\[2pt]
            \text{s.t.}\; -v\mathbf{1} \leq \mathbf{x} \leq v\mathbf{1}
          \end{cases}
        \]
        The constraint says $v \geq |x_i|$ for every $i$, so at
        optimality $v = \max_i |x_i| = \|\mathbf{x}\|_\infty$.
      \end{block}

      \begin{block}{General $L_p$ Norm, $p \geq 1$ (Eq.\ 14.18)}
        For the $L_p$ norm
        $\|\mathbf{x}\|_p = \bigl(\sum_i |x_i|^p\bigr)^{1/p}$:
        \[
          \|\mathbf{x}\|_p \;\Rightarrow\;
          \begin{cases}
            \min_{\mathbf{v}}\; \mathbf{1}^{\top}\mathbf{v}\\[2pt]
            \text{s.t.}\; |x_i|^p \leq v_i \;\;\forall\, i
          \end{cases}
        \]
        Each constraint $|x_i|^p \leq v_i$ is a conic constraint
        (second-order cone for $p = 2$, power cone for general $p$)
        handled natively by interior-point solvers.
      \end{block}

      \begin{block}{$L_2$ Norm and Least Squares (Ex.\ 14.10)}
        Minimising the $L_2$ norm $\|\mathbf{A}\mathbf{x} -
        \mathbf{b}\|_2$ is equivalent to minimising its square
        $\|\mathbf{A}\mathbf{x} - \mathbf{b}\|_2^2$ (since the
        square root is a monotonically increasing function, it does
        not change which $\mathbf{x}$ is optimal).  The unconstrained
        minimum has the closed-form solution:
        \[
          \mathbf{x}^* = (\mathbf{A}^{\top}\mathbf{A})^{-1}
                         \mathbf{A}^{\top}\mathbf{b}
        \]
        where $\mathbf{A}^{\top}$ (``A transpose'') denotes the matrix
        with rows and columns swapped, and $(\cdot)^{-1}$ denotes
        matrix inverse.  This is the classic \emph{least-squares
        formula}.
      \end{block}
    \end{column}
    \begin{column}{0.45\textwidth}
      \includegraphics[width=\textwidth]{fig_norm_balls.pdf}
      \vspace{4pt}
      \small\textit{Unit balls for $L_1$ (diamond shape), $L_2$
      (circle), and $L_\infty$ (square) norms in two dimensions.
      The unit ball is the set of all vectors with norm $\leq 1$.
      Each shape corresponds to a different graph implementation.
      The choice of norm determines the shape of the feasible region
      near the optimal solution: $L_1$ encourages sparse solutions
      (many components equal to zero), while $L_2$ encourages balanced
      solutions (components spread more evenly).}
    \end{column}
  \end{columns}

  \begin{alertblock}{Key Insight}
    All of $L_1$, $L_\infty$, and $L_p$ reduce to forms that standard
    LP or conic solvers handle natively.  The DCP system performs
    these reductions automatically --- the user simply writes
    \texttt{cp.norm(x, p)} in Python and the backend receives the
    appropriate LP or SOCP formulation.  The user never needs to
    know which specific solver format is being used.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{CVXPY --- Overview and Workflow}

  \textbf{CVXPY} is the standard Python library for disciplined convex
  programming.  It is the Python counterpart of the Julia library
  \texttt{Convex.jl} used in the textbook.  CVXPY implements the full
  DCP pipeline --- verification, canonicalization, solver invocation,
  and result extraction --- behind a clean and user-friendly Python
  interface.  You write the problem in a natural mathematical notation,
  and CVXPY handles everything else.

  \begin{columns}
    \begin{column}{0.55\textwidth}
      \includegraphics[width=\textwidth]{fig_cvxpy_workflow.pdf}
      \vspace{4pt}
      \begin{block}{What CVXPY Does Internally}
        \begin{enumerate}
          \item \textbf{Parse}: CVXPY builds an expression graph (an
                internal tree representation) from the Python code you
                write.  Each \texttt{cp.*} call creates a node.
          \item \textbf{Verify}: runs the two-stage DCP check on the
                expression graph.  If verification fails, an informative
                error message is raised before any numerical work is done.
          \item \textbf{Canonicalize}: performs linearization and graph
                implementation automatically to produce partitioned
                canonical form.
          \item \textbf{Dispatch}: selects and calls an appropriate
                backend solver (SCS, ECOS, MOSEK, Clarabel, etc.) based
                on the problem type (LP, SOCP, SDP, etc.).
          \item \textbf{Extract}: retrieves the numerical solution values
                from the solver and makes them available as NumPy arrays
                through the \texttt{.value} attribute of each variable.
        \end{enumerate}
      \end{block}
    \end{column}
    \begin{column}{0.42\textwidth}
      \begin{alertblock}{Python vs.\ Julia}
        The textbook uses \texttt{Convex.jl} (Julia).  Python users
        should use \textbf{CVXPY} instead --- the API is nearly
        identical.\\[4pt]
        To install, run in your terminal:\\
        \texttt{pip install cvxpy}\\[4pt]
        CVXPY ships with open-source solvers (SCS, ECOS) bundled;
        commercial solvers (MOSEK, Gurobi) can be added separately for
        larger or specialised problems.
      \end{alertblock}
      \vspace{4pt}
      \begin{block}{Problem Types CVXPY Supports}
        \begin{itemize}
          \item \textbf{LP} --- Linear Programme
          \item \textbf{QP} --- Quadratic Programme
          \item \textbf{SOCP} --- Second-Order Cone Programme
          \item \textbf{SDP} --- Semidefinite Programme
          \item \textbf{GP} --- Geometric Programme
          \item \textbf{MIP} --- Mixed-Integer Programme (partial)

import cvxpy as cp
import numpy as np

# ── Fixed data matrices and vectors ──────────────────────────
A = np.array([[2, -1], [1, 3]])     # 2x2 matrix (fixed)
b = np.array([4, -5])               # 2-vector (fixed)
C = np.array([[0, 1], [3, -4]])     # 2x2 matrix (fixed)
d = np.array([-1, 0])               # 2-vector (fixed)

# ── Decision variable ─────────────────────────────────────────
x = cp.Variable(2)   # x is a 2-dimensional vector variable

# ── Objective: minimise the L1 norm of A @ x - b ────────────
# cp.norm(expr, 1) computes the L1 norm (sum of absolute values)
objective = cp.Minimize(cp.norm(A @ x - b, 1))

# ── Constraint: L1.5 norm of C @ x - d must be <= 3 ─────────
# cp.norm(expr, 1.5) computes the L_{1.5} norm (convex for p>=1)
constraints = [cp.norm(C @ x - d, 1.5) <= 3]

# ── Assemble and solve ────────────────────────────────────────
problem = cp.Problem(objective, constraints)
problem.solve()

print("Status:   ", problem.status)   # should print "optimal"
print("Optimal x:", x.value)          # numpy array of floats
print("Obj value:", problem.value)    # scalar optimal cost
\end{lstlisting}

\begin{frame}[fragile]{CVXPY: Lasso Regression --- Sparse Recovery}
\begin{lstlisting}[caption={L1-regularised least squares (Lasso) for sparse coefficient recovery}]
import cvxpy as cp
import numpy as np

np.random.seed(42)
n, m = 100, 30          # n=100 samples (rows), m=30 features (cols)
A    = np.random.randn(n, m)   # random design matrix
# True coefficient vector: most entries are zero (sparse)
x_true = np.random.randn(m) * (np.random.rand(m) > 0.7)
# Observations: A @ x_true plus small Gaussian noise
b = A @ x_true + 0.1 * np.random.randn(n)

# lambda (lambda): regularisation weight, controls sparsity.
# Large lambda -> more zeros; small lambda -> closer least-squares fit.
lam = 0.5
x   = cp.Variable(m)   # m-dimensional decision variable

# Objective = data fidelity term + sparsity penalty:
#   ||Ax - b||^2 : least-squares fit (convex, differentiable)
#   lambda * ||x||_1 : L1 penalty promotes sparsity (convex)
objective = cp.Minimize(
    cp.sum_squares(A @ x - b) + lam * cp.norm1(x)
)
problem = cp.Problem(objective)
print("Is DCP?:", problem.is_dcp())  # True
problem.solve()

# How many components of x are nonzero (threshold at 0.01)?
print(f"Recovered nonzeros: {np.sum(np.abs(x.value) > 0.01)}")
print(f"True     nonzeros:  {np.sum(np.abs(x_true) > 0)}")
print(f"Residual ||Ax-b||: {np.linalg.norm(A @ x.value - b):.4f}")
\end{lstlisting}

\begin{frame}[fragile]{CVXPY: Mean-Variance Portfolio Optimisation}
\begin{lstlisting}[caption={Markowitz mean-variance portfolio with CVXPY: balance return and risk}]
import cvxpy as cp
import numpy as np

np.random.seed(0)
n   = 10                                    # number of assets
# mu (mu, pronounced "myoo"): vector of expected returns per asset
mu  = np.random.randn(n) * 0.1 + 0.05
# Sigma (Sigma, capital Sigma): covariance matrix of asset returns.
# Positive semidefinite, so cp.quad_form(w, Sig) is convex.
Sig = np.random.randn(n, n)
Sig = Sig.T @ Sig / n + 0.01 * np.eye(n)
# gamma (gamma, pronounced "gam-ma"): risk-aversion coefficient.
# Large gamma -> more risk-averse; small gamma -> chase return.
gamma = 1.0

w = cp.Variable(n)   # w: portfolio weight vector (sums to 1)

# cp.quad_form(w, Sig) = w^T Sigma w = portfolio variance (convex)
# mu @ w              = mu^T w       = expected return (affine in w)
risk      = cp.quad_form(w, Sig)     # convex (Sig is PSD)
ret       = mu @ w                   # affine in w
# Objective: minimise variance - gamma * expected_return.
# This trades off lower risk against higher return.
objective  = cp.Minimize(risk - gamma * ret)
constraints = [
    cp.sum(w) == 1,  # budget: all wealth must be invested
    w >= 0           # long-only: no short selling (no borrowing)
]
problem = cp.Problem(objective, constraints)
print("Is DCP?", problem.is_dcp())  # True
problem.solve()
print(f"Optimal weights: {np.round(w.value, 3)}")
print(f"Expected return: {(mu @ w.value):.4f}")
\end{lstlisting}

\begin{frame}[allowframebreaks]{Interior Point Methods and Block-Diagonal Structure}

  Once the DCP has been converted to partitioned canonical form, it is
  handed to a numerical solver.  The solver of choice for convex
  programmes is an \textbf{interior point method} (also called a
  \emph{barrier method}).  Understanding why interior point methods are
  so efficient for the canonical form helps explain why DCP is not just
  a notational convenience but a genuine algorithmic advantage.

  \begin{block}{How Interior Point Methods Work}
    An interior point method avoids constraint boundaries by adding
    a \emph{logarithmic barrier function} to the objective that
    becomes $+\infty$ at the boundary of the feasible set.  At each
    iteration, it solves a smooth unconstrained problem (the
    barrier-penalised version), then decreases the barrier weight.
    As the weight shrinks to zero, the iterates approach the true
    constrained optimum from the interior of the feasible set.
    Each unconstrained solve requires inverting (or factoring) the
    Hessian $\nabla^2$ (nabla-squared, meaning the matrix of
    second derivatives) of the barrier function.
  \end{block}

  \begin{block}{Block-Diagonal Hessian from Canonical Form}
    For the partitioned canonical form, because the blocks
    $\mathbf{x}^{(1)}, \ldots, \mathbf{x}^{(k)}$ appear independently
    in the set constraints $\mathbf{x}^{(i)} \in S^{(i)}$, the
    barrier Hessian $\nabla^2 p_{\mathrm{barrier}}$ is
    \textbf{block-diagonal}:
    \[
      \nabla^2 p_{\mathrm{barrier}}(\mathbf{x}) \;=\;
      \begin{bmatrix}
        \nabla^2 p^{(1)}_{\mathrm{barrier}}(\mathbf{x}^{(1)}) & & \\
        & \ddots & \\
        & & \nabla^2 p^{(k)}_{\mathrm{barrier}}(\mathbf{x}^{(k)})
      \end{bmatrix}
    \]
    where $\nabla^2 p^{(i)}_{\mathrm{barrier}}$ (``nabla-squared of
    p-barrier sub-i'') is the Hessian of the barrier for block $i$
    alone, which depends only on $\mathbf{x}^{(i)}$ and not on any
    other block.
  \end{block}

  \begin{block}{Notation}
    \begin{itemize}
      \item $\nabla^2$ (``nabla-squared'', from $\nabla$ (nabla,
            meaning gradient/del)) denotes the Hessian matrix of
            second partial derivatives of a scalar function.  For a
            function of $n$ variables, it is an $n \times n$ symmetric
            matrix.  Its $(i,j)$ entry is the second derivative with
            respect to the $i$-th and $j$-th variables simultaneously.
      \item $p_{\mathrm{barrier}}$ is the barrier-augmented objective:
            the sum of the original linear cost and the logarithmic
            penalty terms for each constraint.
      \item A matrix is \textbf{block-diagonal} if all entries outside
            the square blocks on the main diagonal are zero.  Solving a
            linear system with a block-diagonal matrix of blocks of
            sizes $s_1, s_2, \ldots, s_k$ costs $\sum_i O(s_i^3)$
            operations, which is much cheaper than the $O((\sum_i
            s_i)^3)$ cost for a fully dense matrix of the same total
            size.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read This Formula}
    Because the Hessian is block-diagonal, inverting it costs roughly
    the \emph{sum} of the cost for each block individually, rather
    than the cost for the full dense matrix.  For a problem with $k$
    equal-sized blocks of size $s$, this is a factor of $k^2$ cheaper
    --- potentially thousands of times faster for large, well-structured
    problems.  This is the computational payoff of DCP canonicalization:
    it directly enables the solver to exploit the block structure for
    dramatic speed improvements.
  \end{alertblock}

  \begin{columns}
    \begin{column}{0.50\textwidth}
      \includegraphics[width=\textwidth]{fig_interior_point.pdf}
    \end{column}
    \begin{column}{0.47\textwidth}
      The figure illustrates the trajectory of an interior point method:
      starting from the interior of the feasible region (not at the
      boundary), the iterates follow a smooth \emph{central path} that
      curves inward toward the optimum.  Because the Hessian is
      block-diagonal at each step, each Newton step is fast.  The
      method typically converges in 20--80 iterations regardless of
      problem size --- a dramatic improvement over gradient methods that
      may need thousands.
    \end{column}
  \end{columns}

\end{frame}

\begin{frame}[allowframebreaks]{Chapter Summary}

  This chapter developed the complete pipeline for disciplined convex
  programming, from problem specification all the way through to
  numerical solution.  Each stage of the pipeline addresses one distinct
  challenge: (1) how to verify that a problem is convex, (2) how to
  convert it into a form solvers can accept, and (3) how to efficiently
  solve the resulting structured problem.

  \begin{block}{Key Takeaways}
    \begin{enumerate}
      \item \textbf{DCP provides a grammar for convex problems.}
            By requiring expressions to be product-free compositions of
            atoms from a curated library, DCP makes convexity
            checkable automatically by software.  The human writes a
            high-level model; the computer verifies its correctness and
            translates it to a solver-ready format.

      \item \textbf{Verification is a two-stage tree walk.}  Stage~1
            checks the algebraic structure (no variable products).
            Stage~2 propagates curvature labels (convex/concave/affine)
            up the expression tree using sign, composition, and
            top-level rules.  Both stages run in time linear in the
            problem size --- essentially instantaneous.

      \item \textbf{Canonicalization separates modelling from solving.}
            Linearization (replacing atom calls with variables plus
            constraints) and graph implementation (replacing atom
            constraints with linear or conic ones) convert any valid
            DCP into a partitioned canonical form.  This form has a
            purely linear objective and block-structured set constraints.

      \item \textbf{Interior point methods exploit canonical structure.}
            The block-diagonal Hessian of the canonical form
            dramatically reduces the cost of each Newton step, making
            large DCP problems tractable.  Interior point methods
            typically converge in 20--80 iterations, with each
            iteration fast due to the block structure.

      \item \textbf{CVXPY implements the full pipeline in Python.}
            Writing \texttt{cp.Variable}, \texttt{cp.Minimize},
            \texttt{cp.Problem}, and \texttt{problem.solve()} is all
            the user needs.  Verification, canonicalization, solver
            selection, and result extraction all happen automatically
            and correctly behind the scenes.
    \end{enumerate}
  \end{block}

  \medskip
  Reading the diagram: the user writes a \textbf{Disciplined Convex
  Program}, which is first \textbf{verified} using the \textbf{Atom
  Library} to check that every expression satisfies the curvature
  grammar.  If verification passes, the problem is \textbf{canonicalized}
  using \textbf{linearization} and \textbf{graph implementations} (both
  drawing on the atom library for their conic representations), and the
  resulting partitioned canonical form is handed to an
  \textbf{interior-point solver}.  The solver returns the globally
  optimal solution.

  \begin{alertblock}{The Central Theme}
    At every stage, the key principle is the same: separate concerns.
    The atom library separates ``what functions are convex'' from ``how
    to check convexity at runtime''.  Verification separates ``is this
    valid?'' from ``how do I solve it?''.  Canonicalization separates
    ``expressing the problem'' from ``choosing a solver''.  This
    separation of concerns is what makes DCP scalable, reliable, and
    extensible.
  \end{alertblock}

\begin{frame}[allowframebreaks]{Selected Exercises with Guidance}

  \begin{block}{Exercise 14.1 --- Extended-Value Functions}
    Recall that a function $f$ defined on a convex set $\mathcal{S}$
    (``script S'') can be extended to all of $\mathbb{R}^n$ by setting
    $f(\mathbf{x}) = +\infty$ for $\mathbf{x} \notin \mathcal{S}$.
    Define the extended function $g$ formally:
    $g(\mathbf{x}) = f(\mathbf{x})$ if $\mathbf{x} \in \mathcal{S}$,
    else $g(\mathbf{x}) = +\infty$.  Show that $g$ is convex.

    \textbf{Approach:} To prove convexity you must show that for any
    two points $\mathbf{x}, \mathbf{y} \in \mathbb{R}^n$ and any
    $\lambda$ (lambda, pronounced ``lam-duh'') $\in [0,1]$:
    \[
      g\bigl(\lambda\mathbf{x} + (1-\lambda)\mathbf{y}\bigr) \leq
      \lambda\, g(\mathbf{x}) + (1-\lambda)\,g(\mathbf{y}).
    \]
    \textit{Hint}: There are three cases.  (1) Both $\mathbf{x}$ and
    $\mathbf{y}$ lie in $\mathcal{S}$: the convex combination
    $\lambda\mathbf{x}+(1-\lambda)\mathbf{y}$ also lies in
    $\mathcal{S}$ (since $\mathcal{S}$ is convex), so apply the
    convexity of $f$ to get $g(\lambda\mathbf{x}+(1-\lambda)\mathbf{y})
    \leq \lambda f(\mathbf{x}) + (1-\lambda)f(\mathbf{y}) = \lambda
    g(\mathbf{x}) + (1-\lambda)g(\mathbf{y})$.  (2) Exactly one of
    $\mathbf{x}, \mathbf{y}$ lies in $\mathcal{S}$: the right-hand side
    contains $+\infty$, so the inequality holds trivially.  (3) Neither
    lies in $\mathcal{S}$: both sides equal $+\infty$, so the inequality
    holds with equality.
  \end{block}

  \begin{block}{Exercise 14.2 --- Squares in DCP}
    Products of two variables $x_1 \cdot x_2$ are not DCP-compliant
    because their curvature cannot be determined from the curvatures of
    the individual factors alone.  However, $x^2$ is a special case
    that can be handled by defining a \texttt{square}$(x)$ atom with
    the following properties stored in the atom library: curvature =
    convex; nondecreasing for $x \geq 0$; nonincreasing for $x \leq
    0$; range = $[0, \infty)$.

    Using these properties, apply the composition rule to verify that
    $\mathrm{square}(g(\mathbf{x}))$ is convex when $g$ is affine.
    Then construct an example where $g$ is concave and determine
    whether the composition is convex, concave, or neither.

    \textit{Hint}: The sign of $g(\mathbf{x})$ determines which
    monotonicity branch applies --- this is why the range of $g$
    matters, not just its curvature.
  \end{block}

  \begin{block}{Exercise 14.5 --- Graph Implementation of $\sqrt{x}$}
    The square root function $\sqrt{x}$ is \textbf{concave} on
    $x \geq 0$, so its \emph{hypograph} is used for the graph
    implementation.  The hypograph is:
    \[
      \mathrm{hypo}\,\sqrt{x} \;=\;
      \bigl\{(x,y) \mid x \geq 0,\; y \leq \sqrt{x}\bigr\}
      \;=\; \bigl\{(x,y) \mid x \geq 0,\; y^2 \leq x,\; y \geq 0\bigr\}
    \]
    (squaring both sides of $y \leq \sqrt{x}$ for $y \geq 0$ gives
    $y^2 \leq x$, which is a second-order cone constraint).  The graph
    implementation is therefore:
    \[
      \sqrt{x} \;\Rightarrow\; \arg\max_{y \geq 0}\; y
      \quad\text{s.t.}\quad y^2 \leq x
    \]
    Verify numerically in CVXPY that \texttt{cp.sqrt(x)} with $x = 4$
    returns $2.0$.  Then verify that \texttt{cp.sqrt(cp.square(x))}
    equals $|x|$ for a few test values.
  \end{block}

  \begin{block}{Exercise 14.6 --- Full Canonicalization by Hand}
    Consider the running problem:
    \[
      \min_{\mathbf{x}}\;\|\mathbf{A}\mathbf{x} - \mathbf{b}\|_1
      \quad\text{s.t.}\quad
      \|\mathbf{C}\mathbf{x} - \mathbf{d}\|_{1.5} \leq 3
    \]
    Perform the full canonicalization by hand.

    \textbf{Step 1 --- Linearize}: introduce $\mathbf{v}^{(1)} \in
    \mathbb{R}^2$ for the $L_1$ objective (one component per component
    of $\mathbf{A}\mathbf{x} - \mathbf{b}$) and $\mathbf{v}^{(2)} \in
    \mathbb{R}^2$ for the $L_{1.5}$ constraint.

    \textbf{Step 2 --- Graph expand $L_1$}:
    $-\mathbf{v}^{(1)} \leq \mathbf{A}\mathbf{x} - \mathbf{b} \leq
    \mathbf{v}^{(1)}$; the objective becomes
    $\mathbf{1}^{\top}\mathbf{v}^{(1)}$.

    \textbf{Step 3 --- Graph expand $L_{1.5}$}:
    $|(\mathbf{C}\mathbf{x} - \mathbf{d})_i|^{1.5} \leq v_i^{(2)}$
    for $i=1,2$, and $\mathbf{1}^{\top}\mathbf{v}^{(2)} \leq 3$.

    \textbf{Step 4}: Write out the complete LP/SOCP and count the
    total number of variables (original plus all auxiliary) and total
    number of constraints.  Verify your result by solving the problem
    with CVXPY on the specific numerical data.
  \end{block}

\begin{frame}[fragile]{CVXPY: Solving Exercise 14.6 Numerically}
\begin{lstlisting}[caption={Numerical solution of the mixed-norm problem (Ex.\ 14.6) with full reporting}]
import cvxpy as cp
import numpy as np

# ── Problem data (same as the running example) ───────────────
A = np.array([[2., -1.], [1.,  3.]])
b = np.array([4., -5.])
C = np.array([[0.,  1.], [3., -4.]])
d = np.array([-1., 0.])

x = cp.Variable(2)

# ── Build the DCP ────────────────────────────────────────────
objective   = cp.Minimize(cp.norm(A @ x - b, 1))
constraints = [cp.norm(C @ x - d, 1.5) <= 3]
problem     = cp.Problem(objective, constraints)
print("Is DCP:", problem.is_dcp())  # True -- passes verification

# ── Solve with ECOS (interior-point SOCP solver) ─────────────
problem.solve(solver=cp.ECOS, verbose=False)

# ── Report results ────────────────────────────────────────────
print(f"Status          : {problem.status}")
print(f"Optimal x       : {x.value}")         # should be ~[1.23, -0.45]
print(f"Objective value : {problem.value:.6f}") # L1 norm at optimal x
# Check whether the constraint is active (binding) at the optimum:
print(f"||Cx-d||_1.5    : {float(cp.norm(C@x-d, 1.5).value):.4f}")
# A value close to 3.0 means the constraint is active at optimality.
\end{lstlisting}
  \begin{block}{Expected Output (Approximate)}
    \texttt{Status: optimal}\\
    \texttt{x $\approx$ [1.23,\; -0.45]}\\
    \texttt{Obj $\approx$ 6.14}\\
    \texttt{||Cx-d||\_1.5 $\approx$ 3.00}
    (the constraint is \emph{active} at the optimum, meaning the
    inequality is tight --- the optimal solution lies exactly on the
    boundary of the feasible region)
  \end{block}

\begin{frame}[allowframebreaks]{Further Reading and Online Resources}

  \begin{block}{Primary References}
    \begin{itemize}
      \item M.\ Grant, S.\ Boyd, Y.\ Ye,
            ``\textit{Disciplined Convex Programming},''
            in \textit{Global Optimization: From Theory to
            Implementation}, Springer, pp.\ 155--210, 2006.
            This is the foundational paper that introduces the DCP
            framework, formalises the atom library, composition rules,
            and canonicalization pipeline.  Reading this paper gives
            the mathematical derivation of every algorithm in this
            chapter.

      \item S.\ Diamond, S.\ Boyd,
            ``\textit{CVXPY: A Python-Embedded Modeling Language for
            Convex Optimization},''
            \textit{Journal of Machine Learning Research (JMLR)},
            vol.\ 17, pp.\ 1--5, 2016.
            Describes the design and implementation of CVXPY, including
            its extensions to mixed-integer and parametric programmes.
            Read this for a deeper understanding of how CVXPY works
            internally.

      \item S.\ Boyd, L.\ Vandenberghe,
            \textit{Convex Optimization}, Cambridge University Press,
            2004.  The standard reference for convex analysis, duality
            theory, interior point methods, and applications in signal
            processing, machine learning, and control.  Freely
            available at \texttt{cvxbook.stanford.edu}.
    \end{itemize}
  \end{block}

  \begin{block}{Online Resources for Hands-On Practice}
    \begin{itemize}
      \item \texttt{dcp.stanford.edu} --- an interactive DCP analyser
            where you can type expressions and immediately see whether
            they are valid DCP, along with the curvature label assigned

      \item \texttt{cvxpy.org} --- the official CVXPY documentation,

    \end{itemize}
  \end{block}

  \begin{alertblock}{Summary of Chapter 14}
    The fundamental message of disciplined convex programming is that
    \emph{expressing a problem in a disciplined way} --- using an atom
    library and a simple grammar --- enables \emph{fully automatic
    verification and solution}.  This transforms convex optimisation
    from a topic for specialists into a practical everyday tool for
    engineers, data scientists, and operations researchers.
  \end{alertblock}
