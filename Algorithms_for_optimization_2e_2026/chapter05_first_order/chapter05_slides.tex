\section{Introduction to First-Order Methods}
%==============================================================

\begin{frame}[allowframebreaks]{What Are First-Order Methods?}

  \textbf{First-order methods} are optimization algorithms that use
  the \emph{gradient} of the objective function to decide which
  direction to move next.  The word ``first-order'' refers to the
  first derivative (as opposed to second-order methods, which also
  use the Hessian matrix of second derivatives).

  \begin{block}{Definition: First-Order Method}
    A first-order method selects its next iterate using only
    $\nabla f(\vx)$ (nabla $f$ of $\vx$), the vector of all
    first partial derivatives of $f$ evaluated at the current
    point $\vx$.
  \end{block}

  \textbf{Why use the gradient?}  The gradient $\nabla f(\vx)$
  (read ``nabla $f$ at $\vx$'') points in the direction of
  \emph{steepest ascent} of $f$.  Moving in the \emph{opposite}
  direction therefore decreases $f$ as fast as the local linear
  approximation allows.  This is an immediate, geometric insight
  that drives an entire family of practical algorithms.

  \vspace{0.5em}
  \textbf{Computational advantage.}  Computing $\nabla f$ requires
  $O(n)$ work for most structured functions (e.g.\ neural networks
  via backpropagation), where $n$ is the number of parameters.
  By contrast, computing the Hessian requires $O(n^2)$ storage
  alone, making it infeasible for problems with millions of
  parameters.  This is why virtually all modern deep-learning
  systems rely on first-order methods.

  \vspace{0.5em}
  \begin{alertblock}{Requirement}
    The objective $f$ must be \emph{differentiable} at every point
    visited by the algorithm (or at least \emph{sub-differentiable}
    for non-smooth objectives such as the $\ell_1$ norm).
  \end{alertblock}

  \framebreak

  \begin{block}{Chapter Roadmap}
    This chapter develops nine first-order methods in order of
    increasing sophistication.  Each one addresses a specific
    weakness of the previous method:
    \begin{enumerate}
      \item \textbf{Gradient Descent} --- the simplest possible
            first-order method; the foundation for everything else.
      \item \textbf{Conjugate Gradient} --- avoids the zigzag
            behaviour of gradient descent on elongated functions.
      \item \textbf{Momentum (Heavy Ball)} --- adds velocity to
            accelerate progress through flat regions.
      \item \textbf{Nesterov Momentum} --- evaluates the gradient
            one step ahead to reduce overshooting.
      \item \textbf{AdaGrad} --- adapts the step size
            dimension-by-dimension based on gradient history.
      \item \textbf{RMSProp} --- fixes AdaGrad's vanishing step
            size using an exponential moving average.
      \item \textbf{Adadelta} --- eliminates the global learning
            rate entirely using a ratio of two moving averages.
      \item \textbf{Adam} --- combines momentum with adaptive
            learning rates; the standard choice for deep learning.
      \item \textbf{Hypergradient Descent} --- applies gradient
            descent to the step size itself, learning it on the fly.
    \end{enumerate}
  \end{block}

  The key takeaway from this chapter is that there is no single
  ``best'' first-order method: the right choice depends on the
  structure of the problem, the availability of gradient information,
  and computational constraints.

\end{frame}

\section{5.1 Gradient Descent}
%==============================================================

\begin{frame}[allowframebreaks]{5.1 Gradient Descent --- Motivation and Setup}

  Gradient descent is the conceptual starting point for all
  first-order optimization.  The idea is simple: at each
  iteration, compute the gradient of $f$ at the current point,
  then take a step in the opposite direction (the direction of
  steepest descent).

  \vspace{0.5em}
  \textbf{Notation for iterates.}  We write
  $\vx^{(k)}$ (read ``$\vx$ superscript $k$'') to mean the value
  of the decision variable vector at iteration number $k$.

  \begin{block}{Gradient at the $k$-th Iterate}
    \[
      \vg^{(k)} = \nabla f\!\left(\vx^{(k)}\right)
    \]
    Here $\vg^{(k)}$ (bold $g$ superscript $k$) is the
    gradient vector evaluated at the current point $\vx^{(k)}$.
    It lives in $\R^n$ (the space of all real $n$-dimensional
    vectors), where $n$ is the number of decision variables.
    Each component $g_i^{(k)} = \partial f / \partial x_i$
    measures how quickly $f$ increases in the $i$-th coordinate
    direction.
  \end{block}

  \textbf{First-order Taylor approximation.}  Any smooth
  function $f$ can be approximated near a point $\vx^{(k)}$
  by a linear (affine) function.  If we move from $\vx^{(k)}$
  by a small displacement $\alpha\vd$ (where
  $\alpha$ (alpha) is a positive scalar and
  $\vd$ is a unit-length direction vector), the value of $f$
  changes approximately as:

  \begin{block}{Linear Approximation}
    \[
      f\!\left(\vx^{(k)}+\alpha\vd\right)
      \;\approx\;
      f\!\left(\vx^{(k)}\right) + \alpha\,\vd^\top\vg^{(k)}
    \]
    \begin{itemize}
      \item $\alpha$ (alpha) is the step factor, also called
            the learning rate; it controls how far we move.
      \item $\vd$ is the direction vector, assumed to have
            unit length $\|\vd\| = 1$
            (where $\|\cdot\|$ denotes the Euclidean norm).
      \item $\vd^\top\vg^{(k)}$ (``$d$ transpose times $g$'')
            is the dot product of $\vd$ and the gradient;
            it measures how much $f$ increases per unit step
            in direction $\vd$.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read This}
    The dot product $\vd^\top\vg^{(k)}$ is maximised when $\vd$
    points in the same direction as $\vg^{(k)}$, and minimised
    (most negative) when $\vd$ points in the opposite direction.
    Therefore, to decrease $f$ as fast as possible, we should
    choose $\vd = -\vg^{(k)}/\|\vg^{(k)}\|$.
  \end{alertblock}

  \framebreak

  \textbf{Deriving the steepest descent direction.}  We want
  to find the unit vector $\vd$ that minimises
  $\vd^\top\vg^{(k)}$ subject to $\|\vd\| = 1$.  By the
  Cauchy--Schwarz inequality, the minimum value is
  $-\|\vg^{(k)}\|$, achieved when:

  \begin{block}{Steepest Descent Direction}
    \[
      \vd^{(k)} = -\frac{\vg^{(k)}}{\norm{\vg^{(k)}}}
    \]
    This is the direction of steepest descent: it is the
    negative of the gradient $\vg^{(k)}$ (nabla $f$ at the
    current point), divided by its magnitude
    $\|\vg^{(k)}\|$ so that the result has unit length.
    Dividing by the norm means $\alpha$ truly controls the
    \emph{distance} moved, not just an unnormalised step.
  \end{block}

  The full gradient descent update rule combines the steepest
  descent direction with the step factor:

  \begin{block}{Gradient Descent Update Rule}
    \[
      \vx^{(k+1)} = \vx^{(k)} + \alpha\,\vd^{(k)}
                  = \vx^{(k)} - \alpha\,\frac{\vg^{(k)}}{\norm{\vg^{(k)}}}
    \]
    Many practical implementations omit the normalisation and
    write $\vx^{(k+1)} = \vx^{(k)} - \alpha\,\vg^{(k)}$; in
    that case $\alpha$ is not the step \emph{length} but a
    scale factor, and its value must be adjusted accordingly.
  \end{block}

  \begin{alertblock}{Key Insight}
    Moving in the direction opposite to the gradient guarantees
    that $f$ decreases (at least for small enough $\alpha$).
    This is because locally, the gradient tells us exactly
    ``uphill,'' so ``downhill'' is the exact opposite.
  \end{alertblock}

  \framebreak

  \textbf{Note on norms.}  The choice of norm used to define
  ``unit direction'' affects which method we recover:
  \begin{itemize}
    \item Using the $L_2$ (Euclidean) norm $\|\vd\|_2 = 1$
          gives \textbf{steepest descent} (the method above).
    \item Using the $L_1$ norm $\|\vd\|_1 = 1$ gives
          \textbf{coordinate descent}, where only one
          component of $\vx$ changes per step.
  \end{itemize}

  \textbf{Convergence guarantee.}  For a function $f$ that is
  $L$-smooth (meaning its gradient does not change too quickly;
  characterised by the Lipschitz constant $L$ (capital el) of
  the gradient) and $\mu$ (mu)-strongly convex (meaning it
  curves upward with curvature at least $\mu > 0$), gradient
  descent with the right step size converges at a linear rate:

  \begin{block}{Convergence Rate for Strongly Convex $f$}
    \[
      \norm{\vx^{(k)}-\vx^*}^2
      \;\le\;
      \left(1 - \frac{\mu}{L}\right)^k
      \norm{\vx^{(1)}-\vx^*}^2
    \]
    Here $\vx^*$ (x star) is the true minimiser (optimal point),
    $\mu$ (mu) is the strong convexity constant (how curved
    the function is near the minimum), $L$ is the Lipschitz
    constant of the gradient (how fast the gradient can change),
    and $k$ is the iteration number.  The ratio $\kappa = \mu/L$
    (kappa, called the condition number) determines how fast
    convergence occurs.
  \end{block}

  \begin{alertblock}{How to Read This}
    The distance from the optimum shrinks by a factor of
    $(1 - \mu/L)$ at every step.  When $\mu \approx L$
    (well-conditioned problem), this factor is close to $0$
    and convergence is fast.  When $\mu \ll L$ (ill-conditioned
    problem, e.g.\ a long narrow valley), the factor is close
    to $1$ and convergence is very slow.  This is gradient
    descent's fundamental weakness.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{5.1 Gradient Descent --- Algorithm}

  The gradient descent algorithm is straightforward to state:
  start somewhere, repeatedly compute the gradient and take a
  step downhill, and stop after a fixed number of iterations
  (or when the gradient is small enough to declare convergence).

  \begin{block}{Algorithm: Gradient Descent (with Normalisation)}
    \textbf{Input}: objective $f$, gradient function $\nabla f$,
    initial point $\vx^{(1)} \in \R^n$,
    step factor $\alpha > 0$ (alpha, the learning rate),
    number of iterations $T$ (a positive integer).\\[4pt]
    \textbf{For} $k = 1, 2, \dots, T$:
    \begin{enumerate}
      \item Evaluate $\vg^{(k)} = \nabla f(\vx^{(k)})$
            (one gradient computation; $O(n)$ cost).
      \item Form the descent direction
            $\vd^{(k)} = -\vg^{(k)}/\norm{\vg^{(k)}}$
            (negative normalised gradient).
      \item Update the point:
            $\vx^{(k+1)} = \vx^{(k)} + \alpha\,\vd^{(k)}$.
    \end{enumerate}
    \textbf{Return} $\vx^{(T+1)}$ as the best estimate of the
    minimiser.
  \end{block}

  \textbf{Cost analysis.}  Each iteration costs exactly one
  gradient evaluation.  For most functions this is $O(n)$,
  making gradient descent practical even when $n$ is in the
  millions.

\end{frame}

\begin{frame}[fragile]{5.1 Gradient Descent --- Python Code}
\begin{lstlisting}[caption={Gradient Descent (Python/NumPy)}]
import numpy as np

def gradient_descent(f, grad_f, x, alpha,
                     n_iter=100, normalize=True):
    """
    f        : objective function
    grad_f   : gradient of f
    x        : initial point (1D numpy array)
    alpha    : step factor (learning rate)
    normalize: if True, use unit step direction
    """
    path = [x.copy()]
    for _ in range(n_iter):
        g = grad_f(x)
        if normalize:
            d = -g / (np.linalg.norm(g) + 1e-15)
        else:
            d = -g          # unnormalized: alpha acts as true scaling
        x = x + alpha * d
        path.append(x.copy())
    return x, np.array(path)

# Example: f(x) = x1^2 * x2
# The gradient is [2*x1*x2, x1^2]
f     = lambda x: x[0]**2 * x[1]
gradf = lambda x: np.array([2*x[0]*x[1], x[0]**2])

x0 = np.array([1.0, 2.0])
x_opt, path = gradient_descent(f, gradf, x0, alpha=0.1)
# path is an array of shape (n_iter+1, 2), one row per iterate
\end{lstlisting}
\end{frame}

    On elongated (ill-conditioned) functions, successive gradient
    directions are nearly perpendicular to each other.  Each step
    undoes part of the progress made by the previous step,
    producing the characteristic zigzag pattern.  The remaining
    methods in this chapter address this exact problem.
  \end{alertblock}

\section{5.2 Conjugate Gradient Method}
%==============================================================

\begin{frame}[allowframebreaks]{5.2 Conjugate Gradient --- Motivation and Conjugacy}

  \textbf{The problem with gradient descent on narrow valleys.}
  On an ill-conditioned quadratic function, the gradient at each
  step points roughly perpendicular to the valley axis.
  Consequently, successive steps cancel each other out, and
  the algorithm zigzags toward the minimum instead of heading
  straight for it.  The \emph{conjugate gradient} (CG) method
  was designed to fix this.

  \vspace{0.5em}
  \textbf{Quadratic objectives.}  CG was originally designed
  to solve the linear system $\mA\vx = -\vb$ exactly, which
  is equivalent to minimising:

  \begin{block}{Quadratic Objective}
    \[
      \min_{\vx\in\R^n}\;
      \tfrac{1}{2}\vx^\top\mA\vx + \vb^\top\vx + c
    \]
    Here $\mA$ (bold capital A) is a symmetric, positive definite
    $n\times n$ matrix (it defines the shape of the bowl),
    $\vb$ (bold b) is a constant vector (it shifts the bowl),
    and $c$ is a scalar constant (it shifts the function value
    but does not affect the location of the minimum).
    When $\mA$ is positive definite, the function is strictly
    convex and has a unique global minimum.
  \end{block}

  \textbf{What does ``conjugate'' mean?}  In ordinary geometry,
  two vectors are orthogonal if their dot product is zero.
  \emph{Conjugacy with respect to $\mA$} is a generalised
  form of orthogonality that accounts for the shape of the
  function.

  \begin{block}{Conjugacy (A-orthogonality)}
    Directions $\vd^{(1)}, \dots, \vd^{(n)}$ are
    \textbf{mutually conjugate} with respect to $\mA$ if:
    \[
      \vd^{(i)\top}\mA\,\vd^{(j)} = 0
      \quad \text{for all } i \ne j
    \]
    When $\mA = \mathbf{I}$ (the identity matrix), this reduces
    to ordinary orthogonality.  For a general positive definite
    $\mA$, conjugate directions are orthogonal in the
    ``stretched'' coordinate system defined by $\mA$.
  \end{block}

  \begin{alertblock}{Key Result}
    If we have $n$ mutually conjugate directions for an
    $n$-dimensional quadratic, we can reach the exact minimum
    in \emph{exactly} $n$ steps, one per direction.
    No quadratic function in $n$ dimensions requires more
    than $n$ CG steps.
  \end{alertblock}

  \framebreak

  \begin{columns}[T]
    \column{0.52\textwidth}
      The figure shows this on a 2-dimensional quadratic ($n=2$):
      CG converges in exactly 2 steps, reaching the exact
      minimum on the second step.  Gradient descent, by contrast,
      would take many more steps due to zigzagging.

      \vspace{0.5em}
      Note that the two search directions in the CG path are
      \emph{not} perpendicular to each other in the usual sense;
      they are conjugate with respect to the Hessian matrix
      $\mA$, meaning they are orthogonal in the warped geometry
      of the quadratic bowl.

    \column{0.46\textwidth}
      \includegraphics[width=\textwidth]{conjugate_gradient}

      \footnotesize Conjugate gradient converges in $n=2$ steps
      on a 2-D quadratic.  The directions are conjugate
      (A-orthogonal) but not geometrically orthogonal.
  \end{columns}

\end{frame}

\begin{frame}[allowframebreaks]{5.2 Conjugate Gradient --- Update Rules}

  The CG algorithm builds up a sequence of conjugate directions
  one at a time, using only information from the current and
  previous gradients (no matrix $\mA$ required for non-quadratic
  generalisations).

  \vspace{0.5em}
  \textbf{Initialisation.}  The first step is ordinary steepest
  descent (there is no previous direction to conjugate against):
  \[
    \vd^{(1)} = -\vg^{(1)}
  \]

  \textbf{Exact line search for quadratics.}  On a quadratic
  function, the ideal step length can be computed exactly
  (without any trial-and-error):
  \begin{block}{Exact Line Search Step Length}
    \[
      \alpha^{(k)} = -\frac{(\vd^{(k)})^\top \vg^{(k)}}
                           {(\vd^{(k)})^\top \mA\,\vd^{(k)}}
    \]
    Here $\alpha^{(k)}$ (alpha superscript $k$) is the step
    length at iteration $k$; it is the unique scalar that
    minimises $f$ along the line $\vx^{(k)} + \alpha\vd^{(k)}$.
    The numerator measures how much $f$ decreases per unit step;
    the denominator measures the curvature in that direction.
  \end{block}

  \textbf{Direction update.}  After the first step, each new
  direction is a combination of the current negative gradient
  and the previous direction:
  \begin{block}{CG Direction Update}
    \[
      \vd^{(k)} = -\vg^{(k)} + \beta^{(k)}\vd^{(k-1)}
    \]
    Here $\beta^{(k)}$ (beta superscript $k$) is a scalar that
    controls how much of the previous direction is mixed in.
    It is chosen to ensure the new direction is conjugate
    (A-orthogonal) to all previous directions.
  \end{block}

  \framebreak

  \textbf{Exact $\beta$ for quadratics (when $\mA$ is known):}
  \[
    \beta^{(k)} = \frac{(\vg^{(k)})^\top \mA\,\vd^{(k-1)}}
                       {(\vd^{(k-1)})^\top \mA\,\vd^{(k-1)}}
  \]
  This requires multiplying vectors by $\mA$, which is
  feasible when $\mA$ is known explicitly.

  \vspace{0.5em}
  \textbf{Approximations for general (non-quadratic) functions.}
  When $\mA$ is unknown or when $f$ is not quadratic, several
  formulas approximate $\beta$ using only gradient vectors:

  \begin{block}{Fletcher--Reeves Update}
    \[
      \beta^{(k)}_{\mathrm{FR}}
      = \frac{(\vg^{(k)})^\top \vg^{(k)}}
             {(\vg^{(k-1)})^\top \vg^{(k-1)}}
    \]
    This is the ratio of the squared norm (squared length) of
    the current gradient to the squared norm of the previous
    gradient.  When the gradient shrinks (good progress),
    $\beta$ decreases, blending less of the old direction.
  \end{block}

  \begin{block}{Polak--Ribi\`{e}re Update}
    \[
      \beta^{(k)}_{\mathrm{PR}}
      = \frac{(\vg^{(k)})^\top\!\left(\vg^{(k)}-\vg^{(k-1)}\right)}
             {(\vg^{(k-1)})^\top \vg^{(k-1)}}
    \]
    The numerator now measures how much the gradient has
    \emph{changed} from the previous step.  Convergence can
    be guaranteed by truncating negative values:
    $\beta^{(k)} = \max(\beta^{(k)}_{\mathrm{PR}},\, 0)$.
    In practice, Polak--Ribi\`{e}re often outperforms
    Fletcher--Reeves on non-quadratic functions.
  \end{block}

  \textbf{Restarting.}  For non-quadratic $f$, the conjugacy
  property is gradually lost over many iterations.  CG is
  therefore \emph{restarted} every $n$ iterations (or when
  $(\vd^{(k)})^\top \vg^{(k)} > 0$, meaning the direction
  is no longer a descent direction): the direction is reset
  to $\vd^{(k)} \leftarrow -\vg^{(k)}$.

  \begin{alertblock}{Key Takeaway}
    Conjugate gradient extends the power of quadratic solvers to
    general smooth functions, converging in $n$ exact steps on
    quadratics and accelerating convergence significantly on
    well-structured non-quadratic functions.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.2 Conjugate Gradient --- Python Implementation}
\begin{lstlisting}[caption={Conjugate Gradient with Fletcher-Reeves Beta (Python/NumPy)}]
import numpy as np

def conjugate_gradient(grad_f, x, n_iter=None, restart=True):
    """
    Non-linear conjugate gradient with Fletcher-Reeves beta.
    grad_f  : function returning gradient vector at x
    x       : initial point (numpy array, length n)
    n_iter  : number of iterations (default 10*n)
    restart : reset direction every n steps for non-quadratic f
    """
    n = len(x)
    if n_iter is None:
        n_iter = 10 * n
    g = grad_f(x)
    d = -g.copy()           # first direction: steepest descent
    path = [x.copy()]

    for k in range(1, n_iter + 1):
        # Simple backtracking line search (Armijo condition)
        alpha = 1.0
        while True:
            x_new = x + alpha * d
            g_new = grad_f(x_new)
            # Accept step if gradient norm decreased (proxy check)
            if np.dot(g_new, g_new) < np.dot(g, g):
                break
            alpha *= 0.5
            if alpha < 1e-10:
                break

        x = x_new
        g_new = grad_f(x)

        # Fletcher-Reeves: ratio of squared gradient norms
        beta = np.dot(g_new, g_new) / (np.dot(g, g) + 1e-30)
        if restart and k % n == 0:
            beta = 0.0          # restart: revert to steepest descent

        g = g_new
        d = -g + beta * d     # blend: negative gradient + old direction
        path.append(x.copy())

    return x, np.array(path)

# Example: minimise quadratic  f(x) = 0.5 * x^T A x + b^T x
A = np.array([[4.0, 1.0], [1.0, 3.0]])
b = np.array([1.0, 2.0])
grad_quad = lambda x: A @ x + b
x0 = np.array([1.5, 1.5])
x_opt, path = conjugate_gradient(grad_quad, x0, n_iter=10)
print("Optimal x:", x_opt)  # should be near [-0.2, -0.6]
\end{lstlisting}
\end{frame}

\section{5.3 Momentum (Heavy Ball)}
%==============================================================

\begin{frame}[allowframebreaks]{5.3 Momentum --- Intuition and Update Rule}

  \textbf{The problem momentum solves.}  In gradient descent,
  each step depends only on the current gradient and has no
  memory of previous steps.  On functions with flat regions
  or narrow valleys, the algorithm makes very little progress
  per step: in flat regions the gradient is tiny, and in
  narrow valleys successive gradients nearly cancel each other
  out.

  \vspace{0.5em}
  \textbf{Physical intuition.}  Imagine a ball rolling down a
  hilly landscape.  Unlike a particle following the instantaneous
  gradient, the ball \emph{accumulates velocity}: it speeds up
  in directions where the force (gradient) is consistently
  pointing the same way, and it damps out oscillations because
  inertia prevents it from making sharp turns.  The momentum
  method mimics this physical process.

  \begin{block}{Momentum Update Rule}
    The method maintains a \textbf{velocity vector}
    $\vv^{(k)}$ (bold $v$ superscript $k$) in addition to
    the position $\vx^{(k)}$:
    \[
      \vv^{(k+1)} = \beta\,\vv^{(k)} - \alpha\,\vg^{(k)}
    \]
    \[
      \vx^{(k+1)} = \vx^{(k)} + \vv^{(k+1)}
    \]
    where:
    \begin{itemize}
      \item $\beta$ (beta) is the momentum decay coefficient,
            chosen in $[0,1)$; it controls how much of the
            old velocity is retained.  A typical value is
            $\beta = 0.9$.
      \item $\alpha$ (alpha) is the step factor (learning rate),
            which scales how strongly the gradient pushes
            the velocity.
      \item $\vg^{(k)} = \nabla f(\vx^{(k)})$ is the gradient
            at the current position.
      \item The velocity is initialised at $\vv^{(1)} = \mathbf{0}$.
    \end{itemize}
  \end{block}

  \begin{alertblock}{How to Read This}
    At each step, the velocity is scaled down by $\beta$ (like
    friction) and then pushed by the current gradient.  If the
    gradient keeps pointing in the same direction over many steps,
    the velocity builds up in that direction.  If the gradient
    oscillates (as in a narrow valley), the oscillations partially
    cancel in the velocity, producing a smoother trajectory.
  \end{alertblock}

  \framebreak

  \textbf{Equivalent heavy ball form.}  The momentum method can
  also be written without an explicit velocity variable by
  substituting $\vv^{(k)} = \vx^{(k)} - \vx^{(k-1)}$:
  \[
    \vx^{(k+1)}
    = \vx^{(k)} - \alpha\,\vg^{(k)}
    + \beta\!\left(\vx^{(k)}-\vx^{(k-1)}\right)
  \]
  This is the ``heavy ball'' form (Polyak, 1964): the third
  term $\beta(\vx^{(k)}-\vx^{(k-1)})$ acts like inertia,
  pulling the next iterate in the direction the last step moved.

  \vspace{0.5em}
  \textbf{Steady-state velocity.}  Suppose the gradient were
  constant at $\vg$ (a reasonable approximation in a local
  neighbourhood).  The velocity would converge to a fixed point:
  \[
    \vv^* = \frac{-\alpha}{1-\beta}\,\vg
  \]
  Comparing to gradient descent (velocity $= -\alpha\vg$), the
  effective step is amplified by a factor of $1/(1-\beta)$.
  For $\beta = 0.9$ this gives a $10\times$ speed-up in
  steady state; for $\beta = 0.99$ it gives $100\times$.

  \begin{columns}[T]
    \column{0.55\textwidth}
      \begin{exampleblock}{Worked Example: Momentum Speed-Up}
        Consider $f(\vx) = 8x_1^2 + x_2^2$ (ill-conditioned,
        ratio 8:1).  Starting from $\vx^{(1)} = [2.5, 2.5]$
        with $\alpha = 0.06$, $\beta = 0.8$:

        \textbf{Iteration 1:}
        $\vg^{(1)} = [40, 5]$,
        $\vv^{(2)} = 0.8\times[0,0] - 0.06\times[40,5] = [-2.4, -0.3]$,
        $\vx^{(2)} = [2.5, 2.5] + [-2.4, -0.3] = [0.1, 2.2]$.

        \textbf{Iteration 2:}
        $\vg^{(2)} = [1.6, 4.4]$,
        $\vv^{(3)} = 0.8\times[-2.4,-0.3] - 0.06\times[1.6,4.4]
                   = [-2.016, -0.504]$,
        $\vx^{(3)} = [0.1,2.2]+[-2.016,-0.504] = [-1.916, 1.696]$.

        The large $\vx_1$ component is quickly reduced.
      \end{exampleblock}

    \column{0.43\textwidth}
      \includegraphics[width=\textwidth]{momentum_comparison}

      \footnotesize Top: standard gradient descent zigzags; bottom:
      momentum damps oscillations and accelerates along the valley axis.
  \end{columns}

  \begin{alertblock}{Key Takeaway}
    Momentum is most helpful when gradients are consistent over
    many steps (flat regions, narrow valleys).  The parameter
    $\beta$ (beta) trades off acceleration against stability:
    too high and the method overshoots; too low and it barely
    improves over gradient descent.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.3 Momentum --- Python Implementation}
\begin{lstlisting}[caption={Gradient Descent with Momentum (Python/NumPy)}]
import numpy as np

def momentum_descent(grad_f, x, alpha=0.01, beta=0.9,
                     n_iter=500):
    """
    Gradient descent with momentum (Heavy Ball method).
    grad_f : function returning the gradient vector at x
    x      : initial point (numpy array)
    alpha  : step factor (learning rate), controls gradient influence
    beta   : momentum decay in [0, 1); 0 = pure gradient descent,
             0.9 = strong momentum (typical choice)
    """
    v = np.zeros_like(x)   # velocity initialised to zero
    path = [x.copy()]

    for _ in range(n_iter):
        g = grad_f(x)
        v = beta * v - alpha * g    # scale down old velocity, add gradient push
        x = x + v                  # move to new position
        path.append(x.copy())

    return x, np.array(path)

# -- Example: narrow quadratic f(x) = 4*x1^2 + 0.5*x2^2
#    Condition number = 8 (quite ill-conditioned)
A = np.diag([8.0, 1.0])
grad_f = lambda x: A @ x

x0 = np.array([2.5, 2.5])

# Without momentum (beta=0 is equivalent to gradient descent)
x_gd, path_gd = momentum_descent(grad_f, x0.copy(),
                                  alpha=0.11, beta=0.0,
                                  n_iter=30)

# With momentum (beta=0.8 gives up to 5x effective step amplification)
x_mom, path_mom = momentum_descent(grad_f, x0.copy(),
                                    alpha=0.06, beta=0.8,
                                    n_iter=30)

print("GD final:",  x_gd)    # converges, but slowly
print("Mom final:", x_mom)   # converges faster
\end{lstlisting}
\end{frame}

\section{5.4 Nesterov Momentum}
%==============================================================

\begin{frame}[allowframebreaks]{5.4 Nesterov Momentum --- Lookahead Gradient}

  \textbf{The key insight of Nesterov (1983).}  Standard
  momentum evaluates the gradient at the \emph{current} position
  $\vx^{(k)}$, but then uses the velocity to move to a
  \emph{different} position.  This is slightly wasteful:
  we evaluate the gradient at a point we are about to leave.
  Why not instead evaluate the gradient at the point we are
  about to \emph{arrive} at?

  \vspace{0.5em}
  \textbf{The lookahead.}  Before computing the gradient, we
  first apply the momentum term $\beta\vv^{(k)}$ (beta times
  $v$ superscript $k$) to get a \emph{lookahead point}
  $\vx^{(k)} + \beta\vv^{(k)}$.  We evaluate the gradient at
  this lookahead point, which gives a more accurate estimate
  of the gradient at the destination.

  \begin{block}{Nesterov Update (Algorithm 5.4)}
    \[
      \vv^{(k+1)} = \beta\,\vv^{(k)}
                   - \alpha\,\nabla f\!\left(\vx^{(k)}+\beta\,\vv^{(k)}\right)
    \]
    \[
      \vx^{(k+1)} = \vx^{(k)} + \vv^{(k+1)}
    \]
    The symbols have the same meaning as in standard momentum:
    $\vv^{(k+1)}$ (bold $v$ superscript $k{+}1$) is the new
    velocity, $\beta$ (beta) $\in[0,1)$ is the momentum decay,
    $\alpha$ (alpha) is the step factor, and
    $\nabla f(\vx^{(k)}+\beta\vv^{(k)})$ is the gradient
    evaluated at the \emph{lookahead} point.
  \end{block}

  \begin{alertblock}{How to Read This}
    Think of it this way: standard momentum first evaluates
    where you are, then uses yesterday's momentum to estimate
    where to go.  Nesterov instead \emph{first commits} to
    moving by the momentum term, then evaluates the gradient
    at that committed location and adjusts.  This ``look before
    you leap'' strategy reduces overshooting and improves
    convergence.
  \end{alertblock}

  \framebreak

  \textbf{Convergence improvement.}  For a convex and smooth
  function $f$, standard gradient descent achieves a
  convergence rate of $O(1/k)$ (the function value error shrinks
  proportionally to $1/k$).  Nesterov momentum achieves
  $O(1/k^2)$, which is provably optimal for first-order methods
  on smooth convex functions.  This is called an
  \emph{accelerated} rate.

  \vspace{0.5em}
  \textbf{Practical cost.}  Nesterov requires one extra
  gradient evaluation per step compared to standard gradient
  descent (evaluating at the lookahead point instead of the
  current point); the asymptotic computational cost is the same.

  \begin{columns}[T]
    \column{0.52\textwidth}
      The figure on the right compares standard momentum and
      Nesterov momentum on the Rosenbrock function, which has
      a curved, narrow valley leading to its minimum at $(1,1)$.
      Nesterov typically overshoots less at sharp turns and
      converges in fewer iterations.

    \column{0.46\textwidth}
      \includegraphics[width=\textwidth]{nesterov_comparison}

      \footnotesize Nesterov momentum (right column) typically
      converges faster on the Rosenbrock function than standard
      momentum (left column).
  \end{columns}

  \begin{alertblock}{Key Takeaway}
    Nesterov momentum is the theoretically optimal first-order
    method for smooth convex functions.  In practice it also
    works well on non-convex problems (such as training neural
    networks) and is often preferred over standard momentum
    when a slightly more careful implementation is acceptable.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.4 Nesterov Momentum --- Python Code}
\begin{lstlisting}[caption={Nesterov Accelerated Gradient Descent (Python/NumPy)}]
import numpy as np

def nesterov_momentum(grad_f, x, alpha=0.001, beta=0.9,
                      n_iter=500):
    """
    Nesterov accelerated gradient descent.
    grad_f : function returning gradient vector at x
    x      : initial point (numpy array)
    alpha  : learning rate (step factor)
    beta   : momentum decay in [0, 1)

    KEY DIFFERENCE from standard momentum:
    gradient is evaluated at the LOOKAHEAD point x + beta*v,
    not at the current point x.
    """
    v = np.zeros_like(x)
    path = [x.copy()]

    for _ in range(n_iter):
        # Evaluate gradient at lookahead position x + beta*v
        g = grad_f(x + beta * v)
        v = beta * v - alpha * g   # update velocity using lookahead grad
        x = x + v                 # move to new position
        path.append(x.copy())

    return x, np.array(path)

# -- Comparison on Rosenbrock function --
# f(x,y) = (1-x)^2 + 100*(y-x^2)^2
# Minimum at (1, 1), notorious for its narrow curved valley.
def rosenbrock_grad(x):
    gx = -2*(1 - x[0]) - 400*x[0]*(x[1] - x[0]**2)
    gy = 200*(x[1] - x[0]**2)
    return np.array([gx, gy])

x0 = np.array([-1.0, 1.0])

x_mom, _ = momentum_descent(rosenbrock_grad, x0.copy(),
                              alpha=0.001, beta=0.9, n_iter=300)
x_nes, _ = nesterov_momentum(rosenbrock_grad, x0.copy(),
                              alpha=0.001, beta=0.9, n_iter=300)
# x_nes should be closer to [1, 1] than x_mom after 300 steps
\end{lstlisting}
\end{frame}

\section{5.5 AdaGrad}
%==============================================================

\begin{frame}[allowframebreaks]{5.5 AdaGrad --- Adaptive Per-Dimension Step Sizes}

  \textbf{The problem AdaGrad solves.}  All methods so far use
  the same step factor $\alpha$ (alpha) for every dimension of
  $\vx$.  This is suboptimal when different dimensions have
  very different gradient magnitudes.  For example, in natural
  language processing, some word features appear very rarely
  (sparse gradient) while others appear constantly (dense
  gradient).  A uniform step factor either moves too little
  for the rare features or too much for the common ones.

  \vspace{0.5em}
  \textbf{AdaGrad's idea} (Duchi et al., 2011): track the
  history of squared gradients for each dimension, and use this
  history to scale the effective step factor.  Dimensions with
  large past gradients get a smaller step; dimensions with small
  past gradients get a larger step.

  \begin{block}{AdaGrad Update}
    Let $s_i^{(k)}$ (s sub $i$ superscript $k$) be the
    accumulated sum of squared gradients for dimension $i$
    up to step $k$:
    \[
      s_i^{(k)} = \sum_{j=1}^{k}\!\left(g_i^{(j)}\right)^2
    \]
    The \textbf{effective step factor} for dimension $i$ is:
    \[
      \alpha_{\mathrm{adagrad},i}^{(k)}
      = \frac{\alpha}{\varepsilon + \sqrt{s_i^{(k)}}}
    \]
    The \textbf{parameter update} is:
    \[
      x_i^{(k+1)} = x_i^{(k)}
        - \alpha_{\mathrm{adagrad},i}^{(k)}\,g_i^{(k)}
    \]
  \end{block}

  \framebreak

  \textbf{Symbol explanations:}
  \begin{itemize}
    \item $s_i^{(k)}$ (s sub $i$ superscript $k$): the running
          sum of squared gradients in dimension $i$ up to and
          including step $k$.  This is a scalar, not a vector.
          It is always non-negative and never decreases.
    \item $\sum_{j=1}^{k}$ (Sigma, meaning ``sum from $j=1$
          to $k$''): add up the values for all past iterations.
    \item $g_i^{(j)}$ (g sub $i$ superscript $j$): the $i$-th
          component of the gradient at step $j$.
    \item $\alpha$ (alpha): a global step factor, typically
          set to $0.01$.
    \item $\varepsilon$ (epsilon): a tiny positive constant,
          typically $10^{-8}$, added to prevent division by zero
          when $s_i^{(k)} = 0$.
    \item $\sqrt{s_i^{(k)}}$: the square root of the accumulated
          squared gradient, which has units of gradient magnitude.
  \end{itemize}

  \begin{alertblock}{How to Read This}
    As a dimension receives more (large) gradient signal over
    time, $s_i$ grows large and $1/\sqrt{s_i}$ becomes small,
    reducing that dimension's effective step size.  Dimensions
    that rarely receive gradient signal keep a larger effective
    step size.  AdaGrad automatically identifies and respects
    these differences without requiring the user to set per-dimension
    learning rates.
  \end{alertblock}

  \framebreak

  \begin{columns}[T]
    \column{0.52\textwidth}
      \begin{exampleblock}{Worked Example: AdaGrad Step Sizes}
        Consider $f(\vx) = x_1^2 + 10x_2^2$ with
        $\vx^{(1)} = [3.5, 3.5]$ and $\alpha = 0.5$.

        \textbf{Step 1:}
        $\vg^{(1)} = [7.0, 70.0]$.
        $s_1^{(1)} = 49$, $s_2^{(1)} = 4900$.
        Effective steps:
        $\alpha_1 = 0.5/\sqrt{49} = 0.5/7 \approx 0.071$,
        $\alpha_2 = 0.5/\sqrt{4900} = 0.5/70 \approx 0.007$.
        Dimension 2 already gets a $10\times$ smaller step!

        \textbf{Step 10:} After accumulating more squared
        gradients, $s_2$ grows much faster than $s_1$,
        so dimension 2's step shrinks even further relative
        to dimension 1.
      \end{exampleblock}

    \column{0.46\textwidth}
      \includegraphics[width=\textwidth]{adagrad_decay}

      \footnotesize AdaGrad's effective step factor
      monotonically decays toward zero over time, which
      eventually stalls progress on long training runs.
  \end{columns}

  \begin{alertblock}{AdaGrad's Weakness}
    Since $s_i^{(k)}$ only ever increases (each new squared
    gradient is added in), the effective step size
    $\alpha/\sqrt{s_i^{(k)}}$ can only decrease.  For problems
    where gradients are consistently large (dense gradient
    tasks like image classification), $s_i$ grows without
    bound and the effective step eventually becomes negligibly
    small, stopping learning before convergence.  This motivates
    RMSProp, which is introduced next.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.5 AdaGrad --- Python Implementation}
\begin{lstlisting}[caption={AdaGrad (Python/NumPy)}]
import numpy as np

def adagrad(grad_f, x, alpha=0.01, eps=1e-8, n_iter=500):
    """
    AdaGrad: adapts per-dimension step factors from gradient history.
    grad_f : gradient function
    x      : initial point
    alpha  : global step factor (default 0.01; try 0.1 to 1.0 in practice)
    eps    : small constant to prevent division by zero
    """
    s = np.zeros_like(x)    # s[i] = cumulative sum of squared gradients in dim i
    path = [x.copy()]

    for _ in range(n_iter):
        g = grad_f(x)
        s += g**2                              # accumulate (s only ever grows)
        x = x - alpha / (np.sqrt(s) + eps) * g  # per-dimension scaled update
        path.append(x.copy())

    return x, np.array(path)

# -- Running example: f(x) = x1^2 + 10*x2^2
#    Gradient: [2*x1, 20*x2]
A = np.diag([2.0, 20.0])
grad_f = lambda x: A @ x

x0 = np.array([3.5, 3.5])
x_opt, path = adagrad(grad_f, x0.copy(), alpha=0.5, n_iter=200)
print("AdaGrad result:", x_opt)   # should be close to [0, 0]

# -- Inspect effective step sizes across iterations
s_accum = np.zeros(2)
for k in range(1, 6):
    g = A @ path[k-1]
    s_accum += g**2
    eff = 0.5 / (np.sqrt(s_accum) + 1e-8)
    print(f"k={k}: effective step = {eff.round(4)}")
    # Notice: effective step in dimension 2 decays much faster
\end{lstlisting}
\end{frame}

\section{5.6 RMSProp}
%==============================================================

\begin{frame}[allowframebreaks]{5.6 RMSProp --- Fixing AdaGrad's Decaying Step}

  \textbf{The core idea.}  AdaGrad's problem is that
  $s_i^{(k)}$ accumulates all squared gradients from the
  very beginning, so it grows without bound.  RMSProp
  (Tieleman and Hinton, 2012) replaces this
  \emph{arithmetic sum} with an
  \textbf{exponential moving average} (EMA), which
  effectively ``forgets'' old squared gradients.
  This allows the effective step size to stabilise rather
  than decay monotonically.

  \begin{block}{RMSProp Update}
    Instead of summing all past squared gradients,
    compute their exponential moving average:
    \[
      \vs^{(k)} = \gamma\,\vs^{(k-1)}
                + (1-\gamma)\,\vg^{(k)}\odot\vg^{(k)}
    \]
    Then apply per-dimension scaling:
    \[
      \vx^{(k+1)} = \vx^{(k)}
        - \frac{\alpha}{\sqrt{\vs^{(k)}} + \varepsilon}
          \odot\,\vg^{(k)}
    \]
    Symbol explanations:
    \begin{itemize}
      \item $\vs^{(k)}$ (bold s superscript $k$): the EMA
            of squared gradients; this is a \emph{vector}
            with one entry per dimension.
      \item $\gamma$ (gamma): the EMA decay rate, typically
            $0.9$.  Values closer to $1$ give a longer memory;
            values closer to $0$ give a shorter memory.
      \item $\odot$ (Hadamard product): elementwise
            multiplication of two vectors.
      \item $\alpha$ (alpha): the global step factor,
            typically $0.001$.
      \item $\varepsilon$ (epsilon) $\approx 10^{-8}$:
            prevents division by zero; also applied
            \emph{inside} the square root for stability.
      \item Division by $\sqrt{\vs^{(k)}}+\varepsilon$ is
            also elementwise.
    \end{itemize}
  \end{block}

  \framebreak

  \begin{alertblock}{How to Read This}
    The EMA computes a weighted average of all past squared
    gradients, where recent gradients get exponentially more
    weight.  If the recent gradients in dimension $i$ are
    consistently large, $s_i$ stays large and the step in
    that dimension is small.  If the recent gradients become
    small (e.g.\ after approaching the minimum), $s_i$ decays
    toward smaller values and the step factor can recover.
    This is the key difference from AdaGrad, where $s_i$ can
    never decrease.
  \end{alertblock}

  \begin{columns}[T]
    \column{0.52\textwidth}
      \begin{block}{AdaGrad vs.\ RMSProp Comparison}
        \footnotesize
        \begin{tabular}{lcc}
          \toprule
          Property & AdaGrad & RMSProp\\
          \midrule
          $\vs$ formula & $\vs \mathrel{+}= \vg^2$ & $\vs = \gamma\vs + (1-\gamma)\vg^2$\\
          $\vs$ over time & Only grows & Stabilises\\
          Effective step & Always decays & Can stabilise\\
          Sparse gradients & Excellent & Good\\
          Dense, long runs & Fails & Robust\\
          \bottomrule
        \end{tabular}
      \end{block}

    \column{0.46\textwidth}
      \includegraphics[width=\textwidth]{adaptive_methods}

      \footnotesize AdaGrad (left), RMSProp (centre), and Adam
      (right) applied to $f(\vx) = x_1^2 + 10x_2^2$.
  \end{columns}

  \begin{alertblock}{Key Takeaway}
    RMSProp is a simple yet effective fix for AdaGrad's vanishing
    step size problem.  It became a standard choice for training
    recurrent neural networks before Adam was introduced, and
    it remains useful when simpler adaptive methods are preferred.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.6 RMSProp --- Python Implementation}
\begin{lstlisting}[caption={RMSProp (Python/NumPy)}]
import numpy as np

def rmsprop(grad_f, x, alpha=0.001, gamma=0.9,
            eps=1e-8, n_iter=500):
    """
    RMSProp: exponential moving average of squared gradients.
    grad_f : gradient function
    x      : initial point
    alpha  : global learning rate (typically 0.001)
    gamma  : EMA decay rate (typically 0.9; controls memory length)
    eps    : small constant for numerical stability
    """
    s = np.zeros_like(x)    # EMA of squared gradients, init at zero
    path = [x.copy()]

    for _ in range(n_iter):
        g = grad_f(x)
        # EMA update: keep fraction gamma of old s, add (1-gamma) of new g^2
        s = gamma * s + (1 - gamma) * g**2
        # Scale update by 1 / (sqrt(s) + eps) elementwise
        x = x - alpha / (np.sqrt(s) + eps) * g
        path.append(x.copy())

    return x, np.array(path)

# -- Example: f(x) = x1^2 + 10*x2^2
#    This is ill-conditioned (ratio 10:1); adaptive methods handle it better.
grad_f = lambda x: np.array([2*x[0], 20*x[1]])
x0 = np.array([3.5, 3.5])

x_rms, path_rms = rmsprop(grad_f, x0.copy(),
                           alpha=0.1, gamma=0.9, n_iter=200)
print("RMSProp result:", x_rms)
# Should be close to [0, 0]

# To see how the EMA step sizes differ from AdaGrad:
# After many iterations, s stabilises for RMSProp
# but keeps growing for AdaGrad.
\end{lstlisting}
\end{frame}

\section{5.7 Adadelta}
%==============================================================

\begin{frame}[allowframebreaks]{5.7 Adadelta --- No Global Learning Rate}

  \textbf{Motivation.}  RMSProp still requires a global learning
  rate $\alpha$ (alpha) that must be manually tuned.  Adadelta
  (Zeiler, 2012) takes the adaptive idea one step further by
  eliminating $\alpha$ entirely.  Instead of scaling by a
  fixed $\alpha$, it uses the ratio of two exponential moving
  averages to automatically determine an appropriate step size.

  \vspace{0.5em}
  \textbf{Units-based motivation.}  The gradient has units
  of $\partial f / \partial x_i$ (change in objective per
  unit change in $x_i$).  The ideal update $\Delta x_i$ should
  have units of $x_i$, not gradient units.  Adadelta achieves
  this unit invariance by forming a ratio that cancels out the
  gradient units.

  \begin{block}{Adadelta Update}
    Maintain two exponential moving averages:
    \begin{align*}
      \vs^{(k)} &= \gamma_s\,\vs^{(k-1)}
                  + (1-\gamma_s)\,\vg^{(k)}\!\odot\!\vg^{(k)}
                  &&\text{(EMA of squared gradients)}\\[4pt]
      \Delta\vx^{(k)} &= -\frac{\sqrt{\vu^{(k-1)}+\varepsilon}}
                                {\sqrt{\vs^{(k)}+\varepsilon}}
                          \odot\vg^{(k)}
                  &&\text{(update step)}\\[4pt]
      \vu^{(k)} &= \gamma_x\,\vu^{(k-1)}
                  + (1-\gamma_x)\,\Delta\vx^{(k)}\!\odot\!\Delta\vx^{(k)}
                  &&\text{(EMA of squared updates)}\\[4pt]
      \vx^{(k+1)} &= \vx^{(k)} + \Delta\vx^{(k)}
                  &&\text{(parameter update)}
    \end{align*}
  \end{block}

  \framebreak

  \textbf{Symbol explanations:}
  \begin{itemize}
    \item $\vs^{(k)}$ (bold s superscript $k$): EMA of
          squared gradients (same as in RMSProp).
    \item $\vu^{(k)}$ (bold u superscript $k$): EMA of
          squared \emph{updates} $\Delta\vx$.
          This tracks the recent history of how large the
          steps have been.
    \item $\gamma_s$ (gamma sub s): decay rate for the
          gradient EMA, typically $0.95$.
    \item $\gamma_x$ (gamma sub x): decay rate for the
          update EMA, typically $0.95$.
    \item $\varepsilon$ (epsilon): small constant added
          to \emph{both} numerator and denominator;
          adding it to the numerator ensures the very
          first step is well-defined (since $\vu^{(0)}=\mathbf{0}$).
    \item $\Delta\vx^{(k)}$ (Delta x superscript $k$):
          the update vector applied to $\vx$ at step $k$;
          ``delta'' denotes a change.
  \end{itemize}

  \begin{alertblock}{How to Read This}
    The numerator $\sqrt{\vu^{(k-1)}}$ has units of update
    magnitude ($x$ units) and the denominator
    $\sqrt{\vs^{(k)}}$ has units of gradient magnitude.
    Their ratio therefore has units of $x$/gradient, which
    is exactly the unit of a (approximate) Hessian inverse
    applied to a gradient.  Adadelta thus mimics a
    Newton-like step without ever computing the Hessian.
  \end{alertblock}

  \begin{columns}[T]
    \column{0.55\textwidth}
      \begin{block}{Typical Hyperparameters}
        \footnotesize
        $\gamma_s = 0.95$, \; $\gamma_x = 0.95$, \;
        $\varepsilon = 10^{-6}$.

        Note: there is \emph{no} $\alpha$ to tune.  This is
        Adadelta's main practical advantage in settings where
        learning rate search is expensive.
      \end{block}

      \vspace{0.5em}
      \textbf{Practical note.}  In practice, Adadelta converges
      reliably but can be slower than Adam in the early
      iterations, because the numerator EMA $\vu$ starts at
      zero and takes time to warm up.

    \column{0.43\textwidth}
      \includegraphics[width=\textwidth]{adadelta}
  \end{columns}

  \begin{alertblock}{Key Takeaway}
    Adadelta eliminates the need to set a global learning rate,
    making it useful for practitioners who want robust ``set
    and forget'' optimisation.  The price paid is two EMA
    hyperparameters ($\gamma_s$ and $\gamma_x$) instead of one,
    though these are far less sensitive than the learning rate.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.7 Adadelta --- Python Implementation}
\begin{lstlisting}[caption={Adadelta (Python/NumPy)}]
import numpy as np

def adadelta(grad_f, x, gamma_s=0.95, gamma_x=0.95,
             eps=1e-6, n_iter=500):
    """
    Adadelta: eliminates the global learning rate entirely.
    grad_f  : gradient function
    x       : initial point
    gamma_s : EMA decay for squared gradients (typical: 0.95)
    gamma_x : EMA decay for squared updates (typical: 0.95)
    eps     : small constant added to BOTH numerator AND denominator
              (critical: numerator eps ensures first step works when u=0)
    """
    s = np.zeros_like(x)   # EMA of squared gradients
    u = np.zeros_like(x)   # EMA of squared updates (starts at 0)
    path = [x.copy()]

    for _ in range(n_iter):
        g = grad_f(x)
        # Update EMA of squared gradients
        s = gamma_s * s + (1 - gamma_s) * g**2
        # Compute update step: ratio of RMS(updates) to RMS(gradients)
        dx = -(np.sqrt(u + eps) / np.sqrt(s + eps)) * g
        # Update EMA of squared updates (using the step just taken)
        u = gamma_x * u + (1 - gamma_x) * dx**2
        x = x + dx
        path.append(x.copy())

    return x, np.array(path)

# -- Example ------------------------------------------------
# f(x) = x1^2 + 10*x2^2, gradient = [2*x1, 20*x2]
grad_f = lambda x: np.array([2*x[0], 20*x[1]])
x0 = np.array([3.5, 3.5])
x_ada, path_ada = adadelta(grad_f, x0.copy(), n_iter=300)
print("Adadelta result:", x_ada)
# Should converge to approximately [0, 0]
# Note: no alpha needed - the algorithm finds its own scale
\end{lstlisting}
\end{frame}

\section{5.8 Adam}
%==============================================================

\begin{frame}[allowframebreaks]{5.8 Adam --- Adaptive Moment Estimation}

  \textbf{What Adam is.}  Adam (Kingma and Ba, 2014) stands for
  \textbf{Ada}ptive \textbf{M}oment estimation.  It combines
  two ideas we have already seen:
  \begin{enumerate}
    \item \textbf{Momentum}: maintain an EMA of the gradient
          itself (the first moment, or mean).
    \item \textbf{RMSProp}: maintain an EMA of the squared
          gradient (the second moment, or uncentered variance).
  \end{enumerate}
  Adam also adds \textbf{bias correction}, which is crucial
  during the first few iterations.

  \begin{block}{Adam Update}
    Track biased first moment $\vv$ (momentum) and biased
    second moment $\vs$ (squared gradient EMA):
    \[
      \vv^{(k)} = \gamma_v\,\vv^{(k-1)} + (1-\gamma_v)\,\vg^{(k)}
    \]
    \[
      \vs^{(k)} = \gamma_s\,\vs^{(k-1)}
                + (1-\gamma_s)\,\vg^{(k)}\!\odot\!\vg^{(k)}
    \]
    Apply \textbf{bias correction} to both:
    \[
      \hat{\vv}^{(k)} = \frac{\vv^{(k)}}{1-\gamma_v^k},
      \qquad
      \hat{\vs}^{(k)} = \frac{\vs^{(k)}}{1-\gamma_s^k}
    \]
    Finally, update the parameters:
    \[
      \vx^{(k+1)} = \vx^{(k)}
        - \alpha\,\frac{\hat{\vv}^{(k)}}{\sqrt{\hat{\vs}^{(k)}}+\varepsilon}
    \]
  \end{block}

  \framebreak

  \textbf{Symbol explanations:}
  \begin{itemize}
    \item $\vv^{(k)}$ (bold v superscript $k$): the biased
          first moment estimate (EMA of gradients), analogous
          to the velocity in momentum.  It gives Adam a
          momentum-like property.
    \item $\vs^{(k)}$ (bold s superscript $k$): the biased
          second moment estimate (EMA of squared gradients),
          analogous to the $\vs$ in RMSProp.
    \item $\gamma_v$ (gamma sub v): decay rate for the first
          moment, typically $0.9$.  A value of $0.9$ means
          each step blends $10\%$ of the new gradient with
          $90\%$ of the accumulated average.
    \item $\gamma_s$ (gamma sub s): decay rate for the second
          moment, typically $0.999$.  This very high value
          means the second moment is a very smooth average
          over a long history.
    \item $\hat{\vv}^{(k)}$ (v-hat superscript $k$): the
          bias-corrected first moment.  The ``hat'' indicates
          a corrected estimate.
    \item $\hat{\vs}^{(k)}$ (s-hat superscript $k$): the
          bias-corrected second moment.
    \item $\gamma_v^k$ (gamma sub v to the power $k$):
          gamma sub v raised to the $k$-th power.
          This quantity decreases toward $0$ as $k$ grows.
    \item $\alpha$ (alpha): global learning rate, typically
          $0.001$.
    \item $\varepsilon$ (epsilon) $\approx 10^{-8}$:
          prevents division by zero.
  \end{itemize}

  \begin{block}{Default Hyperparameters}
    \footnotesize
    \begin{tabular}{lll}
      \toprule
      Parameter & Symbol & Default value\\
      \midrule
      Learning rate & $\alpha$ (alpha) & $0.001$\\
      First moment decay & $\gamma_v$ (gamma sub v) & $0.9$\\
      Second moment decay & $\gamma_s$ (gamma sub s) & $0.999$\\
      Stability constant & $\varepsilon$ (epsilon) & $10^{-8}$\\
      Initial first moment & $\vv^{(0)}$ & $\mathbf{0}$\\
      Initial second moment & $\vs^{(0)}$ & $\mathbf{0}$\\
      \bottomrule
    \end{tabular}
  \end{block}

  \framebreak

  \textbf{Why bias correction is necessary.}  Both $\vv$ and
  $\vs$ are initialised at zero.  After the very first step:
  \[
    \vv^{(1)} = (1-\gamma_v)\,\vg^{(1)}
  \]
  With $\gamma_v = 0.9$, this gives
  $\vv^{(1)} = 0.1\,\vg^{(1)}$, which is only $10\%$ of the
  true gradient.  Without correction, the effective learning
  rate would be ten times smaller than intended during the
  first several iterations.

  Bias correction divides by $1 - \gamma_v^k$:
  \[
    \hat{\vv}^{(k)} = \frac{\vv^{(k)}}{1-\gamma_v^k}
  \]
  At $k=1$: $1 - 0.9^1 = 0.1$, so $\hat{\vv}^{(1)} = \vg^{(1)}$
  (correctly scaled).  As $k \to \infty$: $1-\gamma_v^k \to 1$,
  so the correction factor disappears.

  \begin{alertblock}{How to Read This}
    Bias correction is only important in the \emph{first few
    iterations}.  Without it, the algorithm starts much more
    cautiously than intended.  With it, Adam behaves consistently
    from the very first step onward.
  \end{alertblock}

  \framebreak

  \begin{columns}[T]
    \column{0.50\textwidth}
      \includegraphics[width=\textwidth]{adam_bias_correction}

      \footnotesize Without bias correction (dashed), the
      effective moments are severely underestimated early in
      training.  With correction (solid), they track the
      true values from the start.

    \column{0.48\textwidth}
      \begin{block}{Adam Combines Three Ideas}
        \begin{itemize}
          \item \textbf{Momentum} (via $\vv$): accelerates
                convergence in consistent gradient directions.
          \item \textbf{Adaptive per-dimension scaling}
                (via $\vs$): handles dimensions with different
                gradient magnitudes automatically.
          \item \textbf{Bias correction}: ensures correct
                behaviour from the very first iteration.
        \end{itemize}
        Together these make Adam a robust default for a wide
        range of machine learning problems, especially deep
        learning.
      \end{block}
  \end{columns}

  \begin{alertblock}{Key Takeaway}
    Adam is the most widely used optimizer in deep learning
    today because it works well with minimal hyperparameter
    tuning.  The default hyperparameters $(\alpha=0.001,
    \gamma_v=0.9, \gamma_s=0.999)$ work surprisingly well
    across a broad range of models and datasets.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.8 Adam --- Python Implementation}
\begin{lstlisting}[caption={Adam Optimizer (Python/NumPy)}]
import numpy as np

def adam(grad_f, x, alpha=0.001, gamma_v=0.9, gamma_s=0.999,
         eps=1e-8, n_iter=1000):
    """
    Adam: Adaptive Moment Estimation (Kingma & Ba, 2014).
    grad_f  : gradient function
    x       : initial point
    alpha   : global learning rate (default 0.001; rarely needs tuning)
    gamma_v : first moment (momentum) decay, default 0.9
    gamma_s : second moment (squared grad) decay, default 0.999
    eps     : stability constant, prevents division by zero
    """
    v = np.zeros_like(x)   # biased first moment (momentum), init zero
    s = np.zeros_like(x)   # biased second moment (sq. grad), init zero
    path = [x.copy()]

    for k in range(1, n_iter + 1):
        g = grad_f(x)
        v = gamma_v * v + (1 - gamma_v) * g        # biased first moment
        s = gamma_s * s + (1 - gamma_s) * g**2     # biased second moment
        # Bias correction: divide by (1 - gamma^k)
        v_hat = v / (1 - gamma_v**k)               # corrected first moment
        s_hat = s / (1 - gamma_s**k)               # corrected second moment
        # Parameter update: scale gradient by first moment / sqrt(second moment)
        x = x - alpha * v_hat / (np.sqrt(s_hat) + eps)
        path.append(x.copy())

    return x, np.array(path)

# -- Example ------------------------------------------------
grad_f = lambda x: np.array([2*x[0], 20*x[1]])  # f = x1^2 + 10*x2^2
x0 = np.array([3.5, 3.5])
x_opt, path = adam(grad_f, x0.copy(), alpha=0.3, n_iter=200)
print("Adam result:", x_opt)   # should be close to [0, 0]
\end{lstlisting}
\end{frame}

\begin{frame}[allowframebreaks]{5.8 Adam --- Step-by-Step Worked Example}

  Let us trace through the first few Adam iterations manually
  to build intuition.  We minimise
  $f(\vx) = x_1^2 + 10x_2^2$ starting from
  $\vx^{(1)} = [3.5,\; 3.5]$ with default hyperparameters
  $\alpha = 0.001$, $\gamma_v = 0.9$, $\gamma_s = 0.999$.

  \begin{exampleblock}{Iteration $k=1$}
    \textbf{Gradient:}
    $\vg^{(1)} = [2\times 3.5,\; 20\times 3.5] = [7.0,\; 70.0]$.

    \textbf{First moment:}
    $\vv^{(1)} = 0.9\times[0,0] + 0.1\times[7.0, 70.0] = [0.7,\; 7.0]$.

    \textbf{Second moment:}
    $\vs^{(1)} = 0.999\times[0,0] + 0.001\times[49,\; 4900] = [0.049,\; 4.9]$.

    \textbf{Bias correction} (at $k=1$, denominator $= 1-0.9^1 = 0.1$ and $1-0.999^1 = 0.001$):
    $\hat{\vv}^{(1)} = [0.7/0.1,\; 7.0/0.1] = [7.0,\; 70.0]$.
    $\hat{\vs}^{(1)} = [0.049/0.001,\; 4.9/0.001] = [49,\; 4900]$.

    \textbf{Update:}
    $\vx^{(2)} = [3.5, 3.5] - 0.001\times
    \left[\frac{7.0}{\sqrt{49}+\varepsilon},\;
          \frac{70.0}{\sqrt{4900}+\varepsilon}\right]
    = [3.5, 3.5] - 0.001\times[1,\; 1]
    = [3.499,\; 3.499]$.

    Both dimensions move by exactly $\alpha = 0.001$ per step, because
    the bias-corrected moments yield $\hat{v}_i / \sqrt{\hat{s}_i} \approx 1$.
  \end{exampleblock}

  \framebreak

  \begin{exampleblock}{What Happens Next}
    As iterations continue:
    \begin{itemize}
      \item The bias correction factor $(1-\gamma^k)$ grows toward $1$,
            so the correction becomes less and less important.
      \item The second moment $\hat{s}_i$ adapts to reflect the recent
            gradient magnitude in each dimension, so dimension 2 (with
            gradient $20x_2$, much larger than dimension 1's $2x_1$)
            takes proportionally smaller steps.
      \item The first moment $\hat{v}$ smooths out any gradient noise,
            acting like momentum.
    \end{itemize}
    The net effect is that both $x_1$ and $x_2$ converge to $0$, with
    $x_2$ converging in a similar number of steps as $x_1$ despite
    its much larger gradient, because Adam automatically compensates.
  \end{exampleblock}

\end{frame}

\section{5.9 Hypergradient Descent}
%==============================================================

\begin{frame}[allowframebreaks]{5.9 Hypergradient Descent --- Learning the Learning Rate}

  \textbf{The meta-problem.}  Every gradient-based method
  requires a step factor $\alpha$ (alpha), and choosing it is
  perhaps the most important and frustrating hyperparameter
  decision in practice.  Too small and convergence is
  painfully slow; too large and the algorithm diverges.
  Can we automate this choice?

  \vspace{0.5em}
  \textbf{The idea.}  Treat $\alpha$ as an additional variable
  and apply gradient descent \emph{to it}.  This is called
  \emph{hypergradient descent}: the term ``hyper'' indicates
  we are taking a gradient with respect to a hyperparameter.

  \vspace{0.5em}
  \textbf{Deriving the hypergradient.}  For ordinary gradient
  descent $\vx^{(k+1)} = \vx^{(k)} - \alpha^{(k)}\vg^{(k)}$,
  we want to compute how the function value at the \emph{next}
  iterate depends on the current step size $\alpha^{(k)}$:
  \[
    \frac{\partial f(\vx^{(k+1)})}{\partial \alpha^{(k)}}
    = \left(\vg^{(k+1)}\right)^\top
      \frac{\partial \vx^{(k+1)}}{\partial \alpha^{(k)}}
    = \left(\vg^{(k+1)}\right)^\top
      \frac{\partial}{\partial\alpha^{(k)}}
      \left(\vx^{(k)} - \alpha^{(k)}\vg^{(k)}\right)
  \]
  Since $\vx^{(k)}$ and $\vg^{(k)}$ do not depend on
  $\alpha^{(k)}$, the partial derivative of the bracket is
  simply $-\vg^{(k)}$:
  \begin{block}{Hypergradient of the Step Size}
    \[
      \frac{\partial f(\vx^{(k+1)})}{\partial \alpha^{(k)}}
      = -\left(\vg^{(k+1)}\right)^\top \vg^{(k)}
    \]
    This is the negative dot product of the current and
    previous gradients.  Remarkably, computing it costs
    no extra function evaluations --- we already have both
    $\vg^{(k)}$ and $\vg^{(k+1)}$ from adjacent gradient
    descent steps.
  \end{block}

  \framebreak

  \textbf{The step-size update rule.}  Applying gradient descent
  to $\alpha$ with a ``hyper step factor'' $\mu$ (mu):

  \begin{block}{Hypergradient Step-Size Update}
    \[
      \alpha^{(k+1)}
      = \alpha^{(k)} - \mu \cdot
        \frac{\partial f(\vx^{(k+1)})}{\partial \alpha^{(k)}}
      = \alpha^{(k)} + \mu\,\vg^{(k+1)}\cdot\vg^{(k)}
    \]
    Here $\mu$ (mu) is the \emph{meta-learning rate}: a new
    hyperparameter that controls how quickly $\alpha$ adapts.
    It must be small (e.g.\ $10^{-6}$ to $10^{-4}$) to keep
    the adaptation stable.
  \end{block}

  \begin{alertblock}{How to Read This}
    The dot product $\vg^{(k+1)} \cdot \vg^{(k)}$ measures the
    angle between successive gradients:
    \begin{itemize}
      \item If successive gradients point in the \emph{same}
            direction (dot product $> 0$): the step size was
            conservative; increasing $\alpha$ is safe.
      \item If successive gradients point in \emph{opposite}
            directions (dot product $< 0$): we overshot;
            decreasing $\alpha$ prevents divergence.
    \end{itemize}
    The algorithm is thus self-correcting: it automatically
    detects oscillation (the telltale sign of too-large $\alpha$)
    and reduces the step size.
  \end{alertblock}

  \framebreak

  \begin{columns}[T]
    \column{0.55\textwidth}
      \begin{exampleblock}{Worked Intuition}
        Consider a 1D function with minimum at $x^* = 0$.
        Starting at $x^{(1)} = 1$, $\alpha^{(1)} = 0.5$:

        \textbf{Step 1:} $g^{(1)} = f'(1) > 0$ (gradient
        points right, away from minimum).
        Update: $x^{(2)} = 1 - 0.5 g^{(1)}$.

        \textbf{Step 2:} If $x^{(2)} > 0$, then $g^{(2)} > 0$
        again (same direction).
        Dot product $g^{(2)}\cdot g^{(1)} > 0$:
        both gradients point right, so $\alpha$ increases.

        If $x^{(2)} < 0$ (overshot), $g^{(2)} < 0$ (gradient
        now points left), so dot product $< 0$ and $\alpha$
        decreases automatically.
      \end{exampleblock}

    \column{0.43\textwidth}
      \includegraphics[width=\textwidth]{hypergradient}

      \footnotesize Left: hypergradient GD (solid) vs.\ standard
      GD (dashed).  Right: the step size $\alpha$ adapts over
      iterations, growing when progress is consistent and
      shrinking when oscillation is detected.
  \end{columns}

  \vspace{0.5em}
  \textbf{Extension to Nesterov.}  The hypergradient idea
  extends to Nesterov momentum: the step size $\alpha$ is
  updated using the dot product of successive
  \emph{lookahead gradients} $\nabla f(\vx^{(k)}+\beta\vv^{(k)})$,
  yielding Hyper-Nesterov (Algorithm 5.10 in the book).

  \begin{alertblock}{Key Takeaway}
    Hypergradient descent automatically adapts the learning rate
    during optimisation at essentially no extra cost (one extra
    dot product per step).  The trade-off is that it introduces
    a new meta-hyperparameter $\mu$ (mu), though $\mu$ is
    typically much easier to set than $\alpha$.
  \end{alertblock}

\end{frame}

\begin{frame}[fragile]{5.9 Hypergradient Descent --- Python Implementation}
\begin{lstlisting}[caption={Hypergradient Descent and Hyper-Nesterov (Python/NumPy)}]
import numpy as np

def hypergradient_descent(grad_f, x, alpha0=0.001,
                          mu=1e-6, n_iter=500):
    """
    Hypergradient descent: gradient descent on the step factor alpha.
    grad_f : gradient function
    x      : initial point
    alpha0 : initial step factor (alpha will adapt from here)
    mu     : meta-learning rate (how fast alpha adapts); keep small!
    """
    alpha = alpha0
    g_prev = np.zeros_like(x)   # previous gradient (zero at start)
    path = [x.copy()]

    for _ in range(n_iter):
        g = grad_f(x)
        # Update alpha: increase if gradients consistent, decrease if oscillating
        alpha = alpha + mu * np.dot(g, g_prev)   # hypergradient update
        alpha = max(alpha, 1e-10)                # keep alpha positive
        g_prev = g.copy()                        # save for next step
        x = x - alpha * g
        path.append(x.copy())

    return x, np.array(path)

def hyper_nesterov(grad_f, x, alpha0=0.001, beta=0.9,
                   mu=1e-6, n_iter=500):
    """
    Hyper-Nesterov: hypergradient applied to Nesterov momentum.
    Uses lookahead gradients for the alpha update (Algorithm 5.10).
    """
    alpha = alpha0
    v = np.zeros_like(x)         # velocity vector
    h_prev = np.zeros_like(x)    # previous lookahead gradient
    path = [x.copy()]

    for _ in range(n_iter):
        h = grad_f(x + beta * v)             # gradient at lookahead point
        alpha = alpha + mu * np.dot(h, h_prev)  # meta-update of alpha
        alpha = max(alpha, 1e-10)
        v = beta * v - alpha * h             # velocity update (Nesterov)
        x = x + v                           # position update
        h_prev = h.copy()
        path.append(x.copy())

    return x, np.array(path)
\end{lstlisting}
\end{frame}

\section{Convergence Comparison}

\begin{frame}[allowframebreaks]{Convergence Comparison of All Methods}

  Now that we have seen all nine methods, it is useful to
  compare them side by side on the same test function to
  understand their relative strengths and weaknesses.
  The figure below shows convergence on the ill-conditioned
  quadratic $f(\vx) = x_1^2 + 10x_2^2$, starting from
  $\vx^{(0)} = [3.5,\; 3.5]$.

  \begin{columns}[T]
    \column{0.50\textwidth}
      \includegraphics[width=\textwidth]{convergence_comparison}

      \footnotesize All methods applied to
      $f(\vx)=x_1^2+10x_2^2$, starting from
      $\vx^{(0)}=[3.5,\;3.5]$.  The vertical axis shows
      $f(\vx^{(k)})$ on a logarithmic scale; a steeper
      downward slope means faster convergence.

    \column{0.48\textwidth}
      \small
      \begin{tabular}{lll}
        \toprule
        Method & Convergence & Notes \\
        \midrule
        GD & $O(1/k)$ & Baseline \\
        Conjugate GD & $n$ exact steps & For quadratics \\
        Momentum & $O(1/k)$ & Faster in practice \\
        Nesterov & $O(1/k^2)$ & Optimal for convex $f$ \\
        AdaGrad & $O(1/\sqrt{k})$ & Best for sparse grads \\
        RMSProp & Adaptive & Robust for deep nets \\
        Adadelta & Adaptive & No $\alpha$ needed \\
        Adam & Adaptive & Deep learning default \\
        Hypergradient & Adaptive & Learns $\alpha$ online \\
        \bottomrule
      \end{tabular}
  \end{columns}

  \framebreak

  \textbf{Reading the convergence rates.}  The rate $O(1/k)$
  (read ``big-Oh of one over $k$'') means the error after
  $k$ iterations is at most some constant divided by $k$.
  To halve the error, you need twice as many iterations.
  The rate $O(1/k^2)$ means the error decreases with the
  \emph{square} of the number of iterations: to halve the
  error, you only need $\sqrt{2} \approx 1.41$ times as
  many iterations.  This is why Nesterov's $O(1/k^2)$ is
  called ``accelerated.''

  \vspace{0.5em}
  \textbf{Practical takeaways.}
  \begin{itemize}
    \item For \textbf{deep learning}, Adam is the de-facto
          standard because its default hyperparameters work
          well across a huge variety of architectures and
          loss functions.
    \item For \textbf{smooth convex problems} (e.g.\ logistic
          regression, support vector machines), Nesterov
          momentum achieves the theoretically optimal rate
          and is often the best practical choice.
    \item For \textbf{quadratic problems}, conjugate gradient
          converges in exactly $n$ steps; no other first-order
          method can beat this.
    \item When \textbf{learning rate tuning is expensive},
          Adadelta or hypergradient descent can save
          significant effort.
    \item For \textbf{sparse features} (text, recommendation
          systems), AdaGrad remains competitive because
          its per-dimension scaling perfectly matches the
          varying frequency of features.
  \end{itemize}

  \begin{alertblock}{Key Takeaway}
    No single first-order method is best for all problems.
    Understanding the structure of your problem --- smooth or
    non-smooth, convex or non-convex, sparse or dense gradients,
    short run or long run --- is the key to choosing the
    right optimizer.
  \end{alertblock}

\end{frame}

\begin{frame}[allowframebreaks]{5.10 Summary}

  \begin{columns}[T]
    \column{0.52\textwidth}
      This chapter developed nine first-order methods, each one
      addressing a specific limitation of the previous.  Here
      is a concise summary of the key ideas:

      \begin{block}{Summary of All Methods}
        \begin{itemize}
          \item \textbf{Gradient descent} moves in the direction
                of steepest descent $-\nabla f/\|\nabla f\|$.
                Simple, but zigzags on ill-conditioned functions.
          \item \textbf{Conjugate gradient} avoids the zigzag by
                maintaining directions that are mutually conjugate
                (A-orthogonal), converging in $n$ steps on quadratics.
          \item \textbf{Momentum} accumulates a velocity vector to
                accelerate progress, damping out oscillations and
                accelerating in consistent-gradient directions.
          \item \textbf{Nesterov momentum} evaluates the gradient
                at the anticipated next position (lookahead),
                achieving the optimal $O(1/k^2)$ rate for convex $f$.
          \item \textbf{AdaGrad} scales each dimension's step size
                by the inverse square root of its accumulated squared
                gradient history, benefiting sparse-feature problems.
          \item \textbf{RMSProp} replaces AdaGrad's cumulative sum
                with an exponential moving average, preventing
                the step size from vanishing on long runs.
          \item \textbf{Adadelta} eliminates the global learning rate
                using a ratio of two EMAs, providing unit-invariant
                updates.
          \item \textbf{Adam} combines momentum and adaptive scaling
                with bias correction, making it the robust default
                for deep learning.
          \item \textbf{Hypergradient descent} applies gradient
                descent to the step size itself, adapting $\alpha$
                online at essentially no extra cost.
        \end{itemize}
      \end{block}

    \column{0.46\textwidth}
      \includegraphics[width=\textwidth]{algorithm_tree}

      \footnotesize Taxonomy of first-order methods, showing how
      each method extends or modifies the previous.

      \vspace{0.5em}
      \begin{alertblock}{The Unifying Theme}
        Every method in this chapter starts from the same
        basic idea --- move in the direction that decreases
        $f$ --- and adds one more piece of information or
        structure to do so more effectively.  Understanding
        this progression is the most important takeaway.
      \end{alertblock}
  \end{columns}

\end{frame}

\begin{frame}[allowframebreaks]{5.11 Selected Exercises with Solutions}

  \begin{block}{Exercise 5.1: Normalised Gradient Descent Step}
    For $f(\vx) = x_1 x_2^2$, at $\vx^{(k)} = [1, 2]$,
    compute the normalised gradient descent direction $\vd^{(k)}$.
  \end{block}

  \textbf{Solution.}  We first compute the gradient.  The partial
  derivatives are:
  \[
    \frac{\partial f}{\partial x_1} = x_2^2 = 4,
    \qquad
    \frac{\partial f}{\partial x_2} = 2x_1 x_2 = 4.
  \]
  So $\nabla f(1,2) = [4,\; 4]$ and the unnormalised descent
  direction is $-[4,4]$.  Normalising:
  \[
    \vd^{(k)} = -\frac{[4, 4]}{\|[4,4]\|}
              = -\frac{[4,4]}{\sqrt{32}}
              = \left[-\frac{1}{\sqrt{2}},\, -\frac{1}{\sqrt{2}}\right]
              \approx [-0.707,\; -0.707].
  \]
  The step moves equally in both the $-x_1$ and $-x_2$ directions.

  \bigskip
  \begin{block}{Exercise 5.3: Effect of Too-Large Step Size}
    Apply gradient descent with $\alpha=1$ to $f(x)=x^4$,
    starting at $x^{(1)}=1$.  What happens?
  \end{block}

  \textbf{Solution.}  The gradient is $f'(x)=4x^3$.
  \begin{align*}
    x^{(2)} &= 1 - 1\times f'(1) = 1 - 4 = -3\\
    x^{(3)} &= -3 - 1\times f'(-3) = -3 - 4(-27) = -3 + 108 = 105
  \end{align*}
  The iterates diverge: each step overshoots the minimum at $x=0$
  by a larger and larger amount.  The step size $\alpha=1$ is
  far too large for this function.  A step size of $\alpha \le 0.05$
  would be stable.

  \framebreak

  \begin{block}{Exercise 5.8: Conjugate Gradient on a Quadratic}
    Apply CG to $f(x,y)=x^2+xy+y^2+5$, starting at $(1,1)$.
    How quickly does it converge?
  \end{block}

  \textbf{Solution.}  The gradient is
  $\nabla f(x,y) = [2x+y,\; x+2y]$.
  At $(1,1)$: $\nabla f = [3, 3]$, so the first CG direction is
  $\vd^{(1)} = -[3, 3]$.

  The Hessian (second derivative matrix) is
  $\mathbf{H} = \begin{bmatrix} 2 & 1 \\ 1 & 2 \end{bmatrix}$,
  which is positive definite (both eigenvalues positive: $1$ and $3$).
  Since $n=2$, CG is guaranteed to converge in at most $\mathbf{2}$
  steps to the exact minimum.  The minimum is at $(0,0)$, where
  $f(0,0)=5$ (the constant term).

  \bigskip
  \begin{block}{Exercise 5.6: Why Is Nesterov Better Than Standard Momentum?}
    Explain the improvement Nesterov momentum makes over standard
    momentum.
  \end{block}

  \textbf{Solution.}  In standard momentum, the gradient is evaluated
  at the \emph{current} position $\vx^{(k)}$ before the velocity
  $\vv^{(k)}$ is applied.  In Nesterov momentum, the gradient is
  evaluated at the \emph{lookahead} position
  $\vx^{(k)} + \beta\vv^{(k)}$, which is where the algorithm will
  actually move to if no gradient correction were applied.

  By evaluating the gradient at the destination rather than the
  starting point, Nesterov obtains a more accurate estimate of
  the gradient for the current step.  This prevents overshooting
  because the gradient ``sees'' that it is approaching the minimum
  and begins slowing down earlier.  The result is the provably
  optimal $O(1/k^2)$ convergence rate for smooth convex functions,
  compared to $O(1/k)$ for standard gradient descent.

  \framebreak

  \begin{block}{Exercise 5.10: Heavy Ball Equivalence}
    Show that the heavy ball iterates are identical to those of
    the momentum method.
  \end{block}

  \textbf{Solution.}  Define the velocity as
  $\vv^{(k)} = \vx^{(k)} - \vx^{(k-1)}$ (the change in position
  from the previous to the current step).  The heavy ball update is:
  \[
    \vx^{(k+1)} = \vx^{(k)} - \alpha\vg^{(k)} + \beta\vv^{(k)}
    = \vx^{(k)} - \alpha\vg^{(k)} + \beta\!\left(\vx^{(k)}-\vx^{(k-1)}\right).
  \]
  The implied velocity at step $k+1$ is:
  \[
    \vv^{(k+1)} = \vx^{(k+1)} - \vx^{(k)}
    = -\alpha\vg^{(k)} + \beta\vv^{(k)}.
  \]
  This is exactly the momentum update rule
  $\vv^{(k+1)} = \beta\vv^{(k)} - \alpha\vg^{(k)}$.
  Therefore, the two formulations produce identical iterates;
  they are just different ways of writing the same algorithm.

\end{frame}

\begin{frame}[fragile]{Further Reading --- scipy Example}
  The \texttt{scipy.optimize} library provides a well-tested
  implementation of the conjugate gradient method that can be
  applied to any smooth objective function.  Using it requires
  only providing $f$ and its gradient $\nabla f$:

  \vspace{0.5em}
\begin{lstlisting}[caption={scipy Conjugate Gradient Example}]
from scipy.optimize import minimize
import numpy as np

f     = lambda x: x[0]**2 + 10*x[1]**2
gradf = lambda x: np.array([2*x[0], 20*x[1]])

# Use scipy's conjugate-gradient method (method='CG')
res = minimize(f, [3.5, 3.5],
               jac=gradf,
               method='CG')
print(res.x)      # approximately [0., 0.]
print(res.nit)    # number of CG iterations used
\end{lstlisting}

  \vspace{0.5em}
  The \texttt{minimize} function returns a result object
  \texttt{res} with fields including \texttt{res.x} (the
  optimal point found), \texttt{res.fun} (the minimum
  function value), and \texttt{res.nit} (number of iterations).
  For well-conditioned quadratics like this example, \texttt{method='CG'}
  typically needs very few iterations.
\end{frame}
